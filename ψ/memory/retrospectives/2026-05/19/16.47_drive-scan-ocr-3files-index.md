## Honest Feedback

**Friction 1: per-page timeout ไม่มี backoff ที่ adaptive**
ตอน retry หน้าที่ timeout บางหน้าต้องรอ 5 นาทีต่อหน้า ถ้าเป็นหน้าที่มีรูปภาพหนักๆ 200 DPI ก็ยังช่วยไม่ได้เสมอ ควรมี adaptive delay หรือ lower DPI (100?) เป็น fallback สุดท้าย

**Friction 2: raw_cache อยู่ใน data/ocr_cache ไม่ใช่ /tmp**
ใช้เวลา debug นานกว่าจะพบว่า cache อยู่คนละที่กับ THAI_RAG_DATA_DIR env การ hardcode `/tmp/thai-legal-rag` เป็น default ทำให้สับสนระหว่าง local run (data/) กับ default

**Friction 3: prod image ไม่มี pipeline/**
ทุกครั้งที่ต้อง run pipeline บน prod ต้อง docker cp script เข้าไปก่อน เป็น friction ที่เกิดซ้ำ ควรมีวิธี standard เช่น dedicated ops container หรือ mount volume

## Lessons Learned

1. **file_id parsing ต้องใช้ regex ใน frontmatter boundary** ไม่ใช่ line limit — frontmatter ยาวได้ถ้ามี laws_referenced เยอะ
2. **retry logic ใน re-structure phase ทำงานได้** — หน้าที่ fail ใน retry loop มักผ่านตอน re-structure (แยก API call คนละ request)
3. **prod image drift** — dedup.py ถูก fix local แต่ไม่ถูก build เข้า prod image ต้อง docker cp
