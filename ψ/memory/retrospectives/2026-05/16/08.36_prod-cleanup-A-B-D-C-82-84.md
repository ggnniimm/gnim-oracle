- **Use Qdrant FilterSelector by source_name list** rather than `status` field, because prod payload doesn't have a `status` field (those chunks were indexed when prod md_loader lacked the inactive check, so no status got written). One filter call, one delete operation.

## Lessons Learned

1. **Pre-flight verification of handoff predictions** — when an out-of-session plan predicts a quantity (chunks to delete, files to update, etc.), count before acting. Handoffs predict; reality is the only ground truth.
2. **Surgical-patch flow for prod-local code drift**: `docker cp local-file container:path` → `docker commit container new-tag` → `docker compose restart service`. Total ~1 minute, ~30s downtime. Image tag captures the patch identity. Backup pre-patch first.
3. **Filename normalization is a contract**: prod source_names use `.pdf` form with `+`-encoding from earlier filenames; local MDs use `.md` with `_`-form. Always normalize both sides (`.md↔.pdf`, `+↔_`) when intersecting.
4. **`docker exec -d` + foreground watcher** is the cleanest way to run long-running prod tasks: server-side is detached, client-side polls until a completion marker appears in the log.
5. **Case-insensitive grep on completion patterns** — eval output capitalization varies; use `grep -i` or anchor on numeric `X/84` patterns instead of `PASS` words.
