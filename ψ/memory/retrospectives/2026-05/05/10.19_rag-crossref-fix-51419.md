**1. Trigger re-index ก่อน upload ไฟล์ใหม่**
ผมรัน `force-reindex` บน prod ก่อน scp ไฟล์ใหม่ขึ้น server มันลบ 31 vectors ไปแล้วและเริ่ม embed ด้วยไฟล์เก่าในขณะที่ผม scp อยู่ โชคดีที่ quota retry ช้าพอ แต่ถ้าโชคร้ายก็คงต้อง re-index ซ้ำ ขั้นตอนที่ถูกต้องคือ scp → docker cp → force-reindex เสมอ ไม่ควรสลับลำดับนี้

**2. สรุปข้อวินิจฉัย เป็น anchor chunk ที่สำคัญที่สุด — ควรตรวจก่อนเสมอ**

**3. ตรวจ TC regression หลัง re-index ได้ครบกว่านี้**

## Lessons Learned

1. **สรุปข้อวินิจฉัย = anchor chunk** ที่ RAG ดึงมาก่อนเสมอ — ข้อมูลที่ถูกต้องใน body ของเนื้อหา แต่ไม่มีใน สรุปข้อวินิจฉัย = ตอบผิดในทางปฏิบัติ เมื่อประเมิน doc ใด ให้ดูสรุปข้อวินิจฉัยก่อน ไม่ใช่แค่ search หาคำ
2. **ระเบียบ ข้อ 6 ≠ retrieval signal สำหรับ "บอกเลิกสัญญา"** แม้ ข้อ 6 จะ define อำนาจหัวหน้าหน่วยงานฯ แต่ไม่มีคำ "บอกเลิกสัญญา" → ไม่ถูก retrieve จาก query นั้น เชื่อม "อะไรอยู่ใน corpus" กับ "อะไรจะถูก retrieve" เป็นสองขั้นตอนแยก
3. **SCP → docker cp → force-reindex เสมอ** ห้ามสลับลำดับ หรือจะ embed ด้วยไฟล์เก่าในขณะที่ vectors ถูกลบไปแล้ว
