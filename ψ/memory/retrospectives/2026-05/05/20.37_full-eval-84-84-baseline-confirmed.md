## Honest Feedback

**Friction 1 — Quota throttling ทำให้ eval workflow เจ็บปวดมาก**
เวลาที่ใช้รอ quota retry สะสมเป็นหลายชั่วโมง การ monitor ผ่าน notification ทุก TC ก็เป็นงานที่น่าเบื่อ ควรมี way ที่ดีกว่านี้ในการ run eval — อาจเป็น async batch หรือ rate-limit-aware scheduler ที่ไม่ต้องรอ retry 60-75s ทุกครั้ง

**Friction 2 — SSH session fragility สำหรับ long-running jobs**
การ eval ครั้งแรกตายที่ TC-032 เพราะ SSH ขาด ต้องเริ่มใหม่ทั้งหมด ควรมี runbook ชัดเจนว่า "ถ้า job ใช้เวลา >5 นาที ให้ใช้ nohup เสมอ" และ monitor จาก server-side log

**Friction 3 — TC-071 ยัง intermittent ไม่มีทางแก้ถาวร**
must_contain alternatives ช่วยได้บ้าง แต่ LLM variance ยังทำให้ test ไม่ reproducible 100% ถ้าจะทำ CI/CD จริงๆ ต้องมีนโยบายชัดเจนว่า "fail N ครั้งจาก M รอบถึงจะนับว่า fail จริง"

## Lessons Learned

1. **nohup บน server เสมอสำหรับ job >5 นาที** — อย่า run foreground บน SSH
2. **Eval ผ่านแล้วต้องยืนยัน fails ด้วย 1v1 ก่อนสรุป** — 2 fails ใน full run ≠ 2 fails จริง
3. **3 real users = product-market signal** — kuea จาก MWA เป็น external user คนแรก
