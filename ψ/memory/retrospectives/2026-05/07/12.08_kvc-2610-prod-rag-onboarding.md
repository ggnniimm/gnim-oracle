## Honest Feedback

**Friction 1 — สรุปจาก log ผิวเผินเร็วเกินไป (ซ้ำเดิม)**
Memory `verify-before-act` มีอยู่แล้วบอกชัดเจน "always verify summary claims, diagnose before fixing" แต่ผมก็ยังพลาด ครั้งนี้เห็น 429 หลายบรรทัด → ฟันธง "broken" ทั้งที่ log แสดงเฉพาะ failure (ไม่ log success) ผมต้อง internalize ว่า: เห็นแต่ failure logs ≠ ระบบไม่ทำงาน ต้อง end-to-end test ก่อน claim. Ming ทักด้วยข้อมูลเชิงประสบการณ์ ("เมื่อวานยังใช้ได้") ผมต้องรับข้อมูลนั้นก่อนปกป้องสรุปเดิม

**Friction 2 — Overgeneralization จาก case เดียว**
learning เมื่อวาน "before/after signing dichotomy" ผมสรุปจาก 2 documents (1 ก่อน + 1 หลัง) แล้วทำเป็น rule ทั่วไป Ming ต้องอธิบายให้ฟังว่า "กวจ 30307 = exemption, non-transferable" — concept ที่ผมไม่มีในความรู้ทั่วไปแต่เป็นพื้นฐานของกฎหมายไทย ผมต้องถามก่อนสรุปเป็น rule โดยเฉพาะกับ legal precedents — ในกฎหมายไทย คำวินิจฉัยรายเคส ≠ banding rule

**Friction 3 — Tool scope drift**
prod query CLI พังตั้งแต่แรก (`VECTOR_BACKEND` import error → `rerank` signature mismatch → `top_k` str/int) ผมไปไล่แก้สามชั้นใน script โดยไม่ฉุกคิดว่า code prod อาจ drift จากที่ผม assume ผมควรอ่าน production code ก่อนใช้ ไม่ใช่ adapt script ตาม error ทีละข้อ
