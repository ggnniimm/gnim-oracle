## Architecture Decisions

- **Hybrid model selection**: Pro only for the heaviest phase (verbatim body extract), Flash for cheap phases (classify, anchor). Cost-aware design — limits Pro spend to where it gains the most.
- **Env-toggle (not hardcode)**: `OCR_EXTRACT_MODEL` lets us roll back to Flash via `.env` without a code change. Important since Pro v2 isn't yet eval-validated.
- **Cross-ref injection in CONTENT section, not anchor**: Anchor (`บทสรุปสำหรับสืบค้น`) is at file end and may not be retrieved. CONTENT chunks are reliably retrieved. Per `2026-03-09_crossref-injection-top-ranked-docs.md` rule.

## Lessons Learned

1. **Hybrid model selection works**: Different OCR phases have different requirements. Verbatim body extract benefits from Pro; classify and anchor don't justify the cost. One env var per phase preserves flexibility.

2. **Pro is "smarter" than Flash — interprets verbatim more loosely**: Pro decides what's redundant (dropped tables), simplifies references (truncated law subsections), proactively comments on content (hallucinated quality_note). For corpus that demands faithfulness, prompt rules need to be more explicit, not less.

3. **Cross-ref injection mechanics**: When the answer to a query lives in two chunks (keyword + concept separated by chunk boundary), a single synthesis sentence pairing them in one chunk fixes the retrieval. Dual numeral systems (Thai + Arabic) widen retrieval surface for the same concept.

4. **MEMORY drift mode**: When a session has multiple supersession events the same day, the LATER one needs to edit MEMORY.md too, not just write a new learning. Otherwise MEMORY stays pinned to the earlier (now-stale) finding.

5. **`feedback_memory-vs-filesystem.md`**: Trust filesystem > MEMORY when they contradict. Three red flags trigger immediate verify: (a) path doesn't exist, (b) mtime contradicts memory's timeline, (c) just-observed code wrote to a different path than memory describes.
