## What Worked

- **Advisor intervention before code**: pivoted from "design detection heuristic" to "verify Pro actually fixes 3 TCs first." Saved hours of designing on an unverified premise.
- **Minimal-touch deploy strategy**: discovered prod drift (config.py + gemini_client.py have OCR work uncommitted to local). rsync generator.py + sed prod's file in place. Zero collateral damage to mwaprocure live app.
- **Env-var override design**: `GENERATOR_MODEL` env-var force-overrides routing. Used for the experimental 9-run smoke test (`docker exec -e GENERATOR_MODEL=gemini-2.5-pro ...`). Now serves as emergency rollback switch. Mwaprocure UX unchanged because no `.env` mutation.
- **Detection regex precision**: 4 routed TCs from 84-TC eval, zero noise. Advisor's "2-line check is enough" was right; resisted urge to count Thai-month occurrences or score complexity.

## What Surprised

- **Pro variance ~8%**: 9/9 PASS in step-3 smoke test didn't characterize the real fail rate. Full eval caught TC-082 fail. Combined 12/13 (92%) is real baseline. **3/3 PASS is NOT proof of 100%** — common stats lesson, easy to skip when you're excited about a result.
- **Full eval 3× over ETA**: 77min instead of 17-25min projected. Google Flash infra 503-retry storm slowed every TC. Almost triggered pre-deploy-ETA rule (5×) — landed at 3×, within tolerance. Should price-in throttling for future evals.
- **Prod path drift**: golden_test_cases.json lives at `pipeline/` on prod (bind-mounted), at `eval/` on local. Different paths because run_eval.py is at different paths in each. Confused initial rsync.

## Lessons

1. **Hybrid model routing pattern** (new) — per-query model selection by domain. Surgical fix for problem class, preserves UX for everything else. See learning file.
2. **Sample-size discipline for variance estimation** — 3/3 PASS doesn't prove 100%. ~10 runs minimum to bound a flake rate. Don't ship after a 3-sample.
3. **Verify premise before designing** — advisor lesson. When a multi-step plan hinges on an unproven assumption, the first step should be verifying the assumption, not building infra on top.
4. **Test brittleness re-occurs at parent/child term granularity** — TC-071 (ข้อ 165 → ตามวงเงิน), TC-015 (e-bidding → ประกาศเชิญชวนทั่วไป). When LLM consistently abstracts up one level, the test is over-specific. Pattern: add the parent term to must_contain OR-array, don't try to force the LLM to name the child.
