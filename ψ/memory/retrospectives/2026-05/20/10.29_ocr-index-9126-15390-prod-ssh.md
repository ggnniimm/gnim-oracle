## Honest Feedback

**Friction 1: SSH buffer ทำให้มองไม่เห็น progress**
`docker exec ... | tail -5` ผ่าน SSH ทำให้ output ถูก buffer ทั้งหมด ไม่มี real-time visibility เลย ควรเป็น default ว่าทุก prod command ที่ใช้เวลา >30 วินาที ต้องใช้ nohup + log file เพื่อ decouple execution กับ observation

**Friction 2: ไม่รู้ว่า docker exec ตายตาม SSH หรือไม่**
เป็น question ที่ต้องรู้ก่อนรัน ไม่ใช่รู้หลังจาก SSH drop แล้ว docker exec ไม่ตาม (default behavior) แต่ถ้าไม่รู้ก็ต้องรันใหม่เพื่อยืนยัน เสียเวลา

**Friction 3: Hotspot instability ทำให้ workflow ติดขัดซ้ำๆ**
SSH บน hotspot drop บ่อยมาก ทุกครั้งที่ต้อง connect prod ต้องใช้ hotspot (ISP block port 22) แต่ hotspot เองก็ไม่ stable เป็น single point of failure ที่แก้ยาก ควรคิด workaround เช่น VPN หรือ SSH port อื่นที่ ISP ไม่ block

## Lessons Learned

1. **nohup + server-side log file เสมอ** สำหรับ prod command นาน ๆ ผ่าน SSH — decouple execution กับ observation ทำให้ SSH drop ไม่กระทบ
2. **docker exec ไม่ตายตาม SSH** — แต่ output หายกับ session ถ้าไม่ redirect ไปไฟล์ก่อน
3. **0 new chunks = งานเสร็จแล้ว** — dedup.db คือ source of truth ว่าไฟล์ถูก index ไปแล้วหรือยัง ตรวจ dedup ได้เลยไม่ต้องรัน index ซ้ำ
