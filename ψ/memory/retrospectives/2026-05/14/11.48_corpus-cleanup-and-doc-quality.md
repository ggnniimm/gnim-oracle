## Honest Feedback

**1. Raw cache "complete" misleads**  
ระบบบอก "Raw cache complete" แต่ complete หมายถึง "มีทุก page entry แล้ว" ไม่ใช่ "ทุก page extract สำเร็จ" — ไม่มีการ validate ว่า entry เป็น placeholder หรือ content จริง ทำให้ debug ยากและ user อาจเข้าใจผิดว่าระบบ retry ทุก page จริงๆ ควรแก้ให้ "cache complete" check validate content ด้วย

**2. Pro structuring timeout ไม่สม่ำเสมอ**  
วิ่ง 10 นาทีแล้วก็ยังไม่เสร็จ ทั้งที่ครั้งแรกใช้ 32 วินาที ทำให้ยากต่อการ set timeout ที่ reasonable และ user ไม่รู้ว่าควรรอนานแค่ไหน อาจต้องมี mechanism บอก "Pro กำลัง overloaded" แทนที่จะเป็นแค่ timeout error

**3. Deploy flow ยังต้องการ manual steps**  
SSH blocked → switch hotspot → rsync → force-reindex → eval chain ยังไม่ automated เลย ทุก deploy session ต้องทำซ้ำ steps เดิมด้วย human ทุกขั้นตอน ควรมี deploy script ที่ handle network check, rsync, reindex, eval ใน single command

## Lessons Learned

**raw cache "complete" ≠ content valid — ต้อง validate entry content ก่อน skip**

เมื่อ `pdf_to_markdown` เห็น raw cache "complete" (ครบทุก page entry) จะ skip re-extraction ทั้งหมด แต่ cache อาจมี placeholder entries จาก timeout เก่า การ debug ต้องอ่าน JSON cache ตรงๆ และตรวจสอบ content ของแต่ละ page entry ก่อนสรุปว่า "cache ดี"
