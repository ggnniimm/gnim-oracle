## Honest Feedback

**Friction 1: DEPLOY.md มี Monitoring section ซ้ำหลัง edit**

เวลาเพิ่มส่วนใหม่เข้า DEPLOY.md โดย insert ตรงกลาง ทำให้ Monitoring section เดิม (ด้านล่าง) กลายเป็น duplicate ต้องมา detect และลบออกทีหลัง ถ้า read file ก่อน edit แล้ว plan ตำแหน่งที่จะ insert ให้ชัดก่อน จะไม่เกิด pattern นี้ — เป็น case ของ "edit without full context" ที่เกิดได้ง่ายกับไฟล์ที่ยาว

**Friction 2: drift_check.sh ยังไม่ integrate กับ deploy workflow**

ปัจจุบัน drift_check.sh เป็น manual script ที่ต้องรันด้วยมือ ถ้า integrate เข้า deploy_image.sh (รัน drift_check --quiet ก่อน build เพื่อ capture baseline) หรือ GitHub Actions deploy workflow (รัน post-deploy เพื่อ verify) จะ close the loop ได้มากกว่า แต่ตอนนี้ถือว่า good enough — tool มีอยู่แล้ว แค่ manual trigger

**Friction 3: Pre-commit hook ไม่ได้ commit เข้า repo**

hook อยู่ใน `.git/hooks/` ซึ่งไม่ได้อยู่ใน version control ถ้า clone repo ใหม่หรือมี collaborator คนอื่น hook จะหายไป วิธีที่ถูกต้องกว่าคือเก็บ hook ไว้ใน `scripts/hooks/` แล้วมี setup script ที่ `ln -s` ให้ แต่เนื่องจาก project นี้ Ming ทำคนเดียวและเป็น machine เดิม จึงยอมรับได้ในตอนนี้
