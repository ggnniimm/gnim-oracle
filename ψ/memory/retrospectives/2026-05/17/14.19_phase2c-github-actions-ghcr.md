## Honest Feedback

**Friction 1: .github/ path ควรจับได้ก่อน push**

สร้าง workflows ใน path ผิดแล้ว push ไปก่อน ถ้าตรวจก่อน push ว่า `ls .github/` ที่ repo root (ไม่ใช่ cwd ซึ่งอยู่ใน subproject) จะเห็นทันที pattern ที่ควรทำ: เวลาสร้าง GitHub Actions workflows ต้อง cd ไป repo root ก่อน หรือ verify path ก่อน commit ว่า workflows file อยู่ใน `{repo_root}/.github/workflows/`

**Friction 2: SSH action parameter ต้อง verify ก่อนใช้**

ใช้ `known_hosts` parameter โดยไม่ตรวจ docs ของ `appleboy/ssh-action@v1.0.3` ก่อน ถ้าตรวจ action.yml ของ action นั้นก่อนเขียน workflow จะรู้ทันทีว่า `known_hosts` ไม่มี — มีแค่ `fingerprint` pattern นี้เหมือนกับ "listmodels before guess" ที่เราเคย learn มาแล้ว แต่ extend ไปถึง "check action inputs before using" ด้วย

**Friction 3: deploy-image.yml ไม่มี smoke test แบบ external**

smoke test ปัจจุบันเป็น `curl localhost:8501/healthz` จาก prod host เอง ซึ่งดีกว่าไม่มี แต่ไม่ได้ verify ว่า user ข้างนอก reach ได้จริง (Traefik routing, TLS, domain) ถ้า smoke test ทำ `curl https://mwaprocure.gnim.cloud` จาก runner จะให้ confidence มากกว่า อย่างไรก็ตามนั่นจะ add latency (DNS + TLS handshake) และ runner อาจไม่มี network access ถึง domain ทุกครั้ง เป็น tradeoff ที่ยอมรับได้สำหรับตอนนี้
