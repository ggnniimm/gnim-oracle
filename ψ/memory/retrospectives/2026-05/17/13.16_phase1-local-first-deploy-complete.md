## Honest Feedback

**Friction 1: ARM64 ควรจับได้ก่อน deploy จริง**

ถ้า build.sh มีขั้นตอน verify platform ก่อน save (`docker inspect $TAG | grep Architecture`) หรือมี `--platform linux/amd64` ตั้งแต่แรก จะไม่เกิด incident นี้เลย ปัญหาคือเขียน script โดยไม่นึกถึง "platform assumption" ที่ Mac M-chip ทำให้เกิดขึ้นโดยอัตโนมัติ

**Friction 2: Qdrant network topology ไม่ได้ document ไว้ล่วงหน้า**

prod compose ไม่ expose qdrant port — นั่นเป็น security ที่ถูกต้อง แต่ script ถูกเขียนโดยไม่ได้ verify topology ก่อน ถ้า DEPLOY.md มีส่วน "Network topology" ที่บอกว่า "Qdrant ไม่ expose port — ใช้ผ่าน app container เท่านั้น" จะช่วยคนเขียน script ในอนาคต (รวมถึง AI) ไม่ให้ทำ assumption ผิด

**Friction 3: Plan ที่ดีบนกระดาษยังต้องผ่าน reality check**

Phase 1a plan ดูถูกต้องทั้งหมดก่อน execute แต่พอรันจริงพบว่า: platform ผิด, network path ผิด, pipeline-in-image ขัดกับ principle ทั้งสามข้อนี้ไม่ได้เกิดจาก plan ไม่ดี แต่เกิดจากการที่ plan ไม่ได้ถูก validate ด้วย "what would break?" thinking ก่อนเขียน code จริงๆ
