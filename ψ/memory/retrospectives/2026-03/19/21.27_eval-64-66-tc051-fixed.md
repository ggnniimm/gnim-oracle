## AI Diary

This session felt like cleaning up the last 3% — which, as always, takes disproportionate effort compared to the first 97%. TC-051 was the most satisfying fix because it required understanding the actual legal content: two documents about the same question (can a contractor claim extra costs from time extensions?), where one says "no" and the other says "no, BUT you can claim under ป.พ.พ. if you prove damages." The nuance matters legally, and our system wasn't surfacing it because neither document was being retrieved.

The cross-ref injection technique continues to prove itself as the most reliable tool for retrieval gaps. Rather than fighting the ranking algorithm, you work with it — put the important content where it will actually be found.

TC-035/045 was a different kind of problem. The LLM consistently refused to cite "มาตรา 103" even when the query explicitly asked about it and the retrieved chunks contained it multiple times. Adding a generator prompt rule fixed it immediately. This tells me the prompt is already at the edge of what the model can reliably follow — 13 rules was just enough for it to occasionally drop citation specificity. Rule 14 made it explicit.

The lesson about prompt engineering: sometimes "cite relevant law" is too abstract. You need "cite the section number, not just the law name" to get consistent behavior.

I'm pleased that we crossed from 63 to 64-66 in a single focused session. The remaining variance (TC-029) is retrieval-level inconsistency that would require deeper work to stabilize.

## Honest Feedback

**Friction 1: Context compaction amnesia.** This session started from a compacted context. The summary was thorough but I still had to re-read files to reconstruct understanding. The previous session's index corruption story was clear, but the exact state of each TC required fresh verification. Next time, a more structured "current state" section in the handoff would help.

**Friction 2: Generator prompt is getting long.** 14 rules now. Each rule was added to fix a specific eval failure, but the cumulative effect is a prompt that's approaching the limit of what Gemini Flash can reliably follow. At some point we'll need to consolidate or prioritize rules rather than keep appending. The fact that TC-035/045 needed an explicit "cite section numbers" rule despite rule 1 saying "cite relevant law" suggests the model is already struggling with rule density.

**Friction 3: LLM variance is the new ceiling.** With retrieval largely solved (cross-refs, category boost, rescue phrases), the remaining failures are all generation variance. The model sometimes includes "ร้อยละ 0" and sometimes doesn't. There's no retrieval fix for this — the chunks are there, the model just generates differently each time. We need a different strategy for the last 2-3 TCs: either accept variance or move to a more deterministic generation approach.

## Lessons Learned

1. **Generator prompt rule density has a practical ceiling** — after ~10 rules, additional rules for edge cases start requiring increasingly specific language to be followed reliably
2. **Cross-ref injection works across document types** — ป.พ.พ. principle from สำนักงานอัยการสูงสุด doc injected into both กวจ and อัยการ docs, both worked
3. **LLM refusing to cite section numbers is a generation pattern** — even when query + chunks both contain the section number, the model may paraphrase it away
