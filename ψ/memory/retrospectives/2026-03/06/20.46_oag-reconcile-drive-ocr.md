## AI Diary

This session reminded me of something fundamental about data work: the source of truth is never just one file. The Excel spreadsheet said one thing, the Drive folder said another, and the actual documents contained yet a third reality. Ming's domain knowledge was the final arbiter — he knew that "3/2563" was actually "7/2563" because he'd seen the original documents.

I felt a spike of alarm when I realized we'd deleted two files (7/2563 and 19/2552) that were actually correct — they were "extra" only because the Excel had wrong entries. The OCR cache saved us there. This is exactly why the "Nothing is Deleted" principle matters. Even though we did delete the md files, the OCR cache (a different layer of preservation) still held the content. Multiple layers of backup aren't redundancy — they're insurance against exactly this kind of cascading correction.

The batch OCR flow worked beautifully once set up: 28 files in 4 minutes, zero failures. The retry-file pattern in batch_index.py proved its worth — instead of re-processing all 554 files in the folder, we surgically targeted just the 28 we needed. The central Gemini client with timeouts (built earlier in this session) kept everything smooth.

What struck me most was the human-AI collaboration pattern here. I could automate the comparison, the matching, the OCR — but only Ming could say "that 3 is really a 7" or "those duplicates exist because someone typed the wrong year." Domain knowledge can't be automated.

## Honest Feedback

**Friction 1: Deleting before verifying corrections.** We removed 48 "extra" files in one batch based on a simple set difference against Excel. Then Ming corrected 5 entries, and 2 of those corrections meant we'd deleted valid files. The safer approach would have been: show the list first, get confirmation on ambiguous cases (like the 2552 year outlier), then delete. The OCR cache saved us, but we got lucky.

**Friction 2: Context window pressure.** This was a continuation of a very long session (central client, index rebuild, eval fixes, temperature, then reconciliation). The compaction summary was good but I had to re-derive file lists and re-run the comparison script because I couldn't reference the earlier output directly. For data pipeline work with many small steps, shorter focused sessions might be more effective.

**Friction 3: No dry-run for deletions.** The removal was done programmatically via `os.remove()` in a Python script. There was no "move to trash" step or temporary holding area. For irreversible file operations on untracked data, a staging pattern (move to `/tmp/removed/` first, delete after confirmation) would be safer.

## Lessons Learned

1. **Excel is not ground truth for legal documents** — always cross-check with domain expert before bulk operations. Excel entries had typos (3 vs 7), wrong years (2562 vs 2552), and duplicates (119, 132).
2. **OCR cache as safety net** — even when md_backup files are deleted, OCR cache preserves the content. Multiple data layers provide recovery options.
3. **Retry-file pattern for surgical batch processing** — instead of reprocessing entire folders, create a targeted list of file IDs. 28 files in 4 min vs 554 files in 45+ min.
