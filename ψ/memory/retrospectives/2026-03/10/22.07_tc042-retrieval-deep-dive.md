## AI Diary

This session was a masterclass in "follow the human's instinct." Ming asked "ทำไมไม่เอา ว108 มาตอบ?" and that single question unlocked the real diagnosis. I had been stuck on cross-referencing and prompt engineering for 4 attempts in the morning — all addressing the wrong layer.

The investigation was methodical and satisfying. We traced the failure from "ว108 not retrieved" → "rank 129 in FAISS" → "glossary expansion brings it to rank 5" → "still fails because LLM paraphrases" → "chunk boundary splits the key phrase" → "moved bullet up" → "still fails, confirmed generation failure."

The glossary expansion experiment was illuminating but dangerous. It worked perfectly for TC-042 (ว108 jumped to rank 5!) but broke TC-025 — a classic precision/recall tradeoff. Broad query expansion helps the target query but pollutes others. The rollback was the right call.

I'm frustrated that TC-042 remains unsolved. The phrase "ไม่ต้องรอ" is literally sitting in the chunk sent to Gemini Flash, but the model consistently rewrites it as "สามารถดำเนินการได้" or similar paraphrases. It's semantically correct but misses the eval's exact-match check. The remaining option is prompt engineering — perhaps a rule that forces the model to preserve negation phrases like "ไม่ต้อง..." verbatim. But that risks over-constraining other answers.

The deeper lesson: RAG optimization has layers (retrieval → reranking → chunk selection → generation), and a fix at one layer can create problems at another. We've now optimized retrieval and chunk placement perfectly — the ball is in the generator's court.

## Honest Feedback

1. **Too many rebuild cycles** — 5 index rebuilds in one session (~15 min each = 75 min waiting). Should have validated the chunk content locally before rebuilding. Could inspect metadata.pkl directly after edits to predict chunking behavior.

2. **Glossary expansion was premature** — should have tested impact on other TCs before running full eval. A targeted eval on just TC-042 + a few "บอกเลิกสัญญา" queries would have caught the regression faster without burning a full eval cycle.

3. **The generation failure was already known** — morning session's lesson learned explicitly said "after one rebuild shows right chunks retrieved but TC still failing, STOP retrieval engineering." I violated this by doing 3 more rebuilds on retrieval changes when the problem was already identified as generation. Ming's patience kept us on track.

## Lessons Learned

- Glossary expansion is a double-edged sword: helps target query but can regress others
- CHUNK_SIZE=400 can split bullet lists in สรุปข้อวินิจฉัย — key phrases must be in early bullets
- ว108 ranks low despite being the canonical document because it's procedural text (no questions), while query-matching ข้อหารือ rank higher
