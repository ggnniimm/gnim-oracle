## AI Diary

This session taught me the difference between solvable problems and inherent variance. TC-005 was the same pattern as TC-003 — a retrieval gap that cross-reference injection could close. Straightforward, satisfying, done in 20 minutes.

TC-042 was different. I went through three rounds of adding cross-references to different documents, rebuilding the index each time (about 10 minutes per rebuild). Each time, the retrieval results shifted — different documents appeared in the top 4. The frustrating part was that even when the right document WITH the cross-reference was retrieved, the LLM sometimes chose not to output "ไม่ต้องรอ" in its answer. The information was IN the context but the LLM exercised its own judgment about what to include.

This is a fundamental limit of LLM-based RAG: even with perfect retrieval, you can't guarantee the LLM will reproduce specific phrases. "ไม่ต้องรอให้กระบวนการพิจารณาผู้ทิ้งงานสิ้นสุด" is a nuanced detail buried in a document about many post-termination procedures. The LLM sometimes mentions it, sometimes doesn't. No amount of retrieval engineering can fix that.

I spent about 45 minutes and 3 index rebuilds chasing TC-042 before accepting this. In hindsight, after the second rebuild showed the same FAIL with the right chunks retrieved, I should have checked the actual LLM context and realized it was a generation problem, not a retrieval problem. The third rebuild was wasted effort.

The positive reframe: 45/48 with 3 flaky LLM-generation failures is a genuinely good result. The retrieval system is now sound — every expected document is either retrieved or cross-referenced. The remaining variance is in the LLM's summarization choices, which is a different problem entirely (prompt engineering, not retrieval engineering).

## Honest Feedback

1. **Three index rebuilds for TC-042 was two too many**: After the first rebuild showed TC-042 failing with the right chunks retrieved, I should have immediately diagnosed it as a generation problem. Instead I kept adding more cross-references to more documents, hoping that redundancy would help. It didn't — the issue was never about WHICH documents were retrieved, but about what the LLM chose to say. The clue was right there: "11886 IS retrieved this time but FAIL" should have been the signal to stop.

2. **I should have run TC-005 and checked BEFORE rebuilding for TC-042**: I rebuilt the index after adding the TC-005 cross-reference, verified TC-005 passed, then immediately added TC-042 cross-references and rebuilt AGAIN. If I had added both cross-references before the first rebuild, I would have saved one rebuild cycle (~10 minutes). Sequential thinking when parallel was possible.

3. **The source expansion explanation was too brief**: Ming asked yesterday to explain source expansion removal. I gave a 4-line explanation when this deserved a more thorough walkthrough — what it did, why it seemed like a good idea initially, what went wrong, and what replaced it. Ming is building domain expertise and deserved more context, not just a summary.

## Lessons Learned

- **Distinguish retrieval failures from generation failures**: If the right chunks are in the LLM context but the expected phrase is missing from the answer, it's a generation problem — no amount of retrieval engineering will fix it
- **Check context before rebuilding**: Verify whether the target information reaches the LLM before investing in another index rebuild
- **Cross-reference injection works for retrieval gaps, not for LLM summarization choices**
