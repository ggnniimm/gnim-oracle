## AI Diary

This session was a masterclass in the gap between "document exists" and "document gets retrieved." คำวินิจฉัยที่ 4/2561 has exactly the principle Ming wanted — deduct non-liable days before calculating whether penalties exceed 10% — but it was written under the old ระเบียบ 2535 framework with completely different terminology. No "ร้อยละ 10," no "งดหรือลดค่าปรับ," no "มาตรา 102." Just "ข้อ 131" and "ผิดนัด." The semantic gap between the query and the document was too wide for both BM25 and FAISS to bridge.

I tried three approaches: enriching the target document, enriching a high-rank document's summary, and finally cross-referencing into ว647. The third worked because ว647 is practically guaranteed to be retrieved for any penalty/termination query — it's the master reference document. Placing the cross-ref between the งดลดค่าปรับ section and the บอกเลิกสัญญา section was deliberate — it connects the two concepts in exactly the way Ming's TC-062 asks about.

What impressed me most was Ming's legal precision. I suggested a TC about "counting penalty days." Ming counter-proposed a much better framing: "ค่าปรับเกิน 10% บอกเลิกได้มั๊ย หากมีเหตุงดลดค่าปรับ" — this forces the answer to address the sequence (deduct first, then evaluate), not just list rules. The human is the pattern breaker; I am the pattern keeper.

## Honest Feedback

1. **Three index rebuilds for one TC is too many.** Each rebuild takes 5-8 minutes. The root cause is that I can't test retrieval directly — no simple `python3 pipeline/query.py "search term"` that works without lightrag. I'm forced to rebuild, run eval, check sources, adjust, rebuild again. A retrieval-only test mode would cut iteration time by 70%.

2. **Cross-ref placement is trial and error.** I don't have visibility into which chunks actually get retrieved and at what rank. The eval output shows the final 4 cited sources, but there are 15 reranked candidates I can't see. If I could see the full reranked list with scores, I'd know immediately whether my cross-ref landed in a retrieved chunk or fell into a non-retrieved one.

3. **Flaky TCs are normalizing failure.** TC-011, TC-035, and TC-037 have failed in multiple sessions now. At 62 TCs, having 3 flaky ones means every full eval shows 3 red lines. It's becoming background noise — I no longer investigate whether a failure is real or flaky. That's dangerous. We should either fix the must_contain to be more robust, or mark them as `"flaky": true` in the TC schema so they're reported differently.

## Lessons Learned

- Cross-ref placement in ว647 is more stable than individual คำวินิจฉัย because ว647 is retrieved for almost any procurement query
- Old-framework documents (ระเบียบ 2535) need keyword enrichment to be retrievable by modern-framework queries (พ.ร.บ. 2560)
- TC query framing matters: "บอกเลิกได้มั๊ย หากมีเหตุ..." forces a conditional answer, which is more useful than "หลักเกณฑ์อย่างไร"
