## AI Diary

This session had a satisfying arc: a problem caught immediately, diagnosed quickly, fixed cleanly, then extended into something bigger.

The citation bug was interesting because it was a prompt engineering problem masquerading as a code problem. The `_replace_refs` function existed and worked — but there was nothing to replace, because the LLM was doing something reasonable: writing out the full document name. Rule 5 said "cite the source name" and the LLM obeyed literally. The fix was precise: change the instruction to explicitly require [N] format and forbid writing names in the body. One line of prompt, problem solved. I've seen this pattern before in this project — when LLM behavior is inconsistent or wrong, the first question should be "what does the prompt actually say?" not "what's wrong with the postprocessing code."

The multi-ref fix `[1, 14]` → `[1, 4]` was a nice catch. The original regex `\[(\d+)\]` only matched single numbers, so any comma-separated reference like `[1, 14]` would pass through unmodified with wrong chunk indices. The fix is clean: split on comma, map each number, dedup. Three lines.

The Streamlit rewrite felt like cleaning house. The old app had LightRAG toggles, category dropdowns, references to FAISS — all dead code from the pre-Qdrant era. The new one is minimal: load index once, retrieve+rerank+generate, remap citations, show footnotes. The `_build_source_map` + `_replace_refs` functions now exist in two places (streamlit_app.py and export_answers_html.py) which bothers me slightly, but extracting them to a shared module would require touching more files than the value justifies right now.

The Docker story is what surprised me most about this session. What started as "deploy on a server" became "deploy on this machine first" became "oh, Qdrant local mode doesn't allow concurrent access." That's actually the right order of discovery — the Qdrant lock error that broke the frontend earlier in the session was the symptom; Docker server mode is the actual solution. Now the stack can handle concurrent access from Streamlit, export jobs, and eval runners simultaneously.

The `google-auth` version conflict was a classic pinned-version trap. Local environment had one set of package versions that happened to be compatible; the Docker build tried to install the pinned versions and hit a hard conflict (`google-auth==2.37.0` vs `google-genai>=2.47.0`). The fix is to unpin and let pip solve it. We should probably audit the whole requirements.txt for similar over-pinning.

## Honest Feedback

**Friction 1: Shared citation logic duplicated across two files.** `_build_source_map` and `_replace_refs` now live in both `export_answers_html.py` and `app/streamlit_app.py`. This is a DRY violation. If we change the citation remapping logic (e.g., to handle `[N]` in parenthetical text, or to deduplicate differently), we'll need to update both files. Should be moved to `src/utils/citations.py` or similar. Not done this session because scope was narrow, but the next developer to touch citations will be confused.

**Friction 2: Export job interrupted at TC-020, never completed.** The full 66-TC HTML export has been started and killed twice now — first when context ran out, second when Streamlit needed the Qdrant lock. With Docker Compose running, this is no longer a problem (concurrent access works), but we never actually produced the final `tc_answers.html` with the new [N] citation fix. It should be re-run now that Docker is up.

**Friction 3: requirements.txt over-pinning will keep causing Docker build failures.** The `google-auth` issue won't be the last one. The requirements.txt was written for local development where everything is already installed, not for fresh Docker builds. Several packages are pinned to versions that conflict when pip tries to install them from scratch. Should do a full requirements audit: identify which pins are truly necessary (e.g., `numpy==1.26.4` for FAISS compatibility) vs which are just "what was installed that day."

## Lessons Learned
- When LLM doesn't use expected citation format, check the prompt instruction — not the postprocessing code
- Qdrant local mode (path) = single-process lock. Server mode (QDRANT_URL) = concurrent access. Docker is the clean solution
- Pinned dependencies in requirements.txt can cause Docker build conflicts even when local env works fine — audit which pins are necessary
