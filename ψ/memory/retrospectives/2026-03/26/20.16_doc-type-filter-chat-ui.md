## Honest Feedback

**1. Should have queried Qdrant payload BEFORE writing the filter.** I wrote `FieldCondition(key="doc_type")` without first checking what fields are actually stored. A one-line curl would have shown me `category` immediately. Instead I went through the full write→build→deploy→test→fail cycle. This wasted ~20 minutes.

**2. Too many sequential rebuilds.** Today involved 5+ Docker rebuilds, each triggered by a separate bug. Some of these could have been caught with local testing before building Docker. The project doesn't have a simple way to run the Streamlit app locally (it assumes Docker for the full stack), which makes the iteration loop slow.

**3. The history-aware filter has a scope problem I didn't flag.** Currently once "คำพิพากษา" appears in the last 6 user messages, ALL queries in that window get filtered — even if the user switches topic. Ming hasn't hit this yet, but "แล้ว เรื่องค่าปรับล่ะ" after a court judgment query would get filtered to only คำพิพากษา, which might return wrong results. Should have mentioned this trade-off.

## Lessons Learned

1. **Always query the actual data store before writing filter code** — check what fields exist in Qdrant payload with a quick curl before assuming field names from source code.
2. **History-aware intent can over-persist** — maintaining context across turns is useful but risky if user switches topic mid-conversation. Consider adding an "exit" trigger or limiting to 3 turns instead of 6.
