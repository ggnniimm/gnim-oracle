## AI Diary

This session was a good reminder that debugging RAG eval failures requires tracing the full pipeline — not just the document content, but which document actually gets retrieved. I made the classic mistake: I added the right content to the wrong place. อ.100/2564 has the exact legal principle Ming wanted, but it wasn't being retrieved for TC-051's query. The top-ranked doc was อ.73/2565. So my first fix landed in a doc that the query never touched.

The second discovery was even more basic: the LLM wrote "ประมวลกฎหมายแพ่งและพาณิชย์" (full form) and the test checked "ป.พ.พ." (abbreviation). Two forms, same meaning, test fails. The fix was obvious once seen — array-of-arrays OR logic in must_contain — but it required me to look at the actual answer text, not just the PASS/FAIL verdict.

What I found interesting is the asymmetry: export_answers_csv.py already supported OR logic, but run_eval.py didn't. Two evaluation tools out of sync. This is the kind of technical debt that hides for a long time until a test uses the feature. I fixed both together.

The `tail -f` leak was embarrassing in a small way. I used `tail -f` in a pipe expecting it to exit when `head -10` was satisfied — but tail doesn't know when the other end is done. Ming noticed it from the UI. Good catch. The lesson is simple: never use `tail -f` in a pipeline unless you control both ends, or use `timeout`.

Overall this was a compact, focused session. No architecture changes, no major new features — just making one test pass correctly and cleaning up two small inconsistencies. That's sometimes the most valuable kind of work.

## Honest Feedback

**Friction 1: Retrieved ≠ Indexed.** I added content to อ.100/2564 assuming it would be retrieved — but I hadn't verified which docs actually come up for TC-051's query. I should have checked retrieval first (`--verbose` output) before editing any document. The second edit to อ.73/2565 was only necessary because of this oversight. Always diagnose retrieval before adding cross-refs.

**Friction 2: Two eval tools out of sync.** run_eval.py and export_answers_csv.py both implement must_contain checking, but diverged on array-of-arrays support. This is a maintenance hazard. If there were a shared `_check_case()` utility function used by both, this wouldn't have happened. The codebase has this duplication at a small scale now but it could grow.

**Friction 3: `tail -f` in pipeline.** This is a basic shell mistake that caused a lingering process. Using `tail -f` is appropriate for interactive monitoring, not for pipelines expecting automatic termination. I knew this rule but violated it anyway under time pressure. The fix is to either wait for process completion (`wait PID`) or use `cat` after the process exits.

## Lessons Learned
- Always check which document is top-retrieved for a failing TC (use `--verbose`) BEFORE editing any documents
- array-of-arrays OR logic in must_contain requires consistent support across ALL evaluation tools
- Never use `tail -f` in a pipeline — use `cat` after process exits, or `timeout tail -f`
