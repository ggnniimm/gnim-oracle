## AI Diary

This session was a beautiful example of peeling back layers of a problem. The initial idea — glossary injection to rescue 49821 from the dedup pool — was right, but implementing it required understanding three cascading dependencies I hadn't anticipated.

First, placement matters. I put glossary injection after source expansion, thinking it was a final rescue step. But then source expansion couldn't see the newly injected source. Moving it before source expansion was the obvious fix, but obvious only in hindsight.

Second, ordering matters. Even with correct placement, source expansion iterates over `top` items in order. The glossary-injected item was at position 19, and by then 5 sources had already been expanded (hitting the limit). The fix — priority-sorting glossary items to expand first — was clean and targeted.

Third, selection criteria matter. Source expansion picks the 2 longest chunks per source, which makes sense for general content. But for glossary-injected sources, we specifically need chunks containing the glossary terms. A 458-char chunk about general contract details is less useful than a 389-char chunk containing "ไม่ต้องรอ" (the exact phrase TC-042 needs).

Each fix was small and targeted — no parameter tuning, no index rebuilding. Just understanding the pipeline flow and making each step aware of the others. The whole session felt like threading a needle through three layers of logic.

## Honest Feedback

1. **Context loss from compaction**: This was a continuation session. The summary was comprehensive but I had to re-read multiple files to rebuild working context. The reranker code is complex enough that the summary's description of "source expansion picks longest chunks" wasn't enough — I needed to see the actual iteration order and limits to understand why 49821 wasn't getting expanded. 2. **Background task output buffering**: The `| tail -30` in the background eval command caused 0 bytes of output for the entire ~15-minute run. This is the same stdout buffering issue documented in a previous lesson, but the `tail` pipe makes it worse than just Python buffering. Should run background tasks without pipe filters, or use `stdbuf -oL`.

3. **Iterative debugging cycle**: Each fix required a full retrieval + check cycle (~30s each). The diagnostic script was helpful but I had to write a new one each time to check different aspects (glossary terms, expansion order, chunk content). A reusable diagnostic that shows the full reranker pipeline state for a query would save significant iteration time.

## Lessons Learned

- Pipeline step ordering creates implicit dependencies: glossary injection must come before source expansion for the chain to work
- Selection criteria should match the injection reason: glossary-injected sources should be expanded by glossary term relevance, not by generic "longest chunk" heuristic
- Small, targeted mechanisms (glossary injection = ~30 lines) can solve problems that would otherwise require parameter tuning (increasing top_k, adjusting weights) which has unpredictable side effects
