## AI Diary

The actual coding was quick: a topic filter, a stricter prompt, a timeout fix. But the waiting, debugging, and restarting — that's where the time went.

## Honest Feedback

1. **Gemini stream timeout should have been there from day one**: The OCR pipeline had no timeout on `generate_content_stream`. This is a basic reliability requirement for any API call, especially one processing hundreds of files in batch. I should have noticed this when first reading the code, not after two pipeline hangs. The fact that it worked fine for the existing กวจ corpus (smaller files? fewer API calls?) masked the issue until we scaled up.

2. **Topic filter is crude**: Using `any(kw in text for kw in keywords)` is a substring match on the full document text. A document mentioning "จัดซื้อจัดจ้าง" once in passing (e.g., referencing the พ.ร.บ. in a completely unrelated ruling) could slip through. A better approach would check the frontmatter `topic` field specifically, or use a scoring threshold. For 545 files this is manageable, but at scale we'd need something smarter.

3. **No incremental progress saving**: When the pipeline hung at file 327, all 327 files were indexed but the FAISS index wasn't saved to disk (that happens at the end). If the process had been killed instead of interrupted, we'd have lost all progress. The pipeline needs periodic checkpointing — save every N files, not just at the end.

## Lessons Learned

- Gemini `generate_content_stream` can hang indefinitely on certain PDFs — always set `http_options.timeout`
- Topic filtering at indexing time prevents noise injection better than trying to filter at query time
- OAG คำวินิจฉัย are ~57% procurement-related; the rest span all areas of law
- Pipeline reliability > pipeline speed: timeout + retry > hoping it works
