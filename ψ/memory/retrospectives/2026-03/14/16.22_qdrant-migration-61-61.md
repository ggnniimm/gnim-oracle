## AI Diary

This session was a masterclass in the gap between "data is there" and "data gets used." The cross-ref injections from the previous session were technically correct — the text existed in the MD files. But the chunks in Qdrant were stale copies from before the edit. The dedup system, designed to prevent re-indexing duplicates, was actually preventing the *updated* content from replacing the old. It's a classic write-ahead problem: the dedup DB said "already indexed" for the unchanged chunks, while the old vectors in Qdrant still pointed to pre-edit content.

The fix was tedious but illuminating. I had to build a manual delete-and-reindex pipeline: scroll Qdrant by source_name filter, delete matching points, compute chunk hashes using the exact same enrichment logic as the indexer (metadata prefix + text), delete from dedup DB, then re-index. Every step had to match the indexer's behavior exactly or chunks would be skipped.

The TC-039 fight was the most satisfying. "แก้ไขสัญญา" appeared in 3 places in the retrieved context but Gemini Flash consistently omitted it. Moving it to the **first bullet with bold** in สรุปข้อวินิจฉัย made it 3/3. Position matters more than repetition — the LLM anchors on opening statements.

Reaching 61/61 parity feels like completing a migration properly rather than just "it works." The Qdrant backend is cleaner architecturally and the embedding-2-preview model performs equivalently with the right cross-ref tuning.

## Honest Feedback

**1. Dedup-on-update is a footgun.** The current system has no "update" path — you can only add new chunks. When an MD file changes, old chunks linger in both Qdrant and the dedup DB. I had to manually build a delete+reindex workflow that mirrors the indexer's exact hashing logic. This should be a first-class operation: `index_md_folder.py --force-reindex --file X.md`. The fact that I spent 30 minutes debugging "why aren't my edits showing up" is a clear sign of missing tooling.

**2. Qdrant local mode's 20K warning is noisy.** Every single operation prints `UserWarning: Local mode is not recommended for collections with more than 20,000 points`. With 28K chunks, this drowns real output. Either suppress it or move to Docker mode. The `grep -v UserWarning` workaround is fragile.

**3. BM25 index doesn't support deletion.** When I re-indexed the 3 docs, old BM25 entries persisted alongside new ones. The pickle-based BM25 store has `add_batch` but no `delete`. This means BM25 accumulates stale data on every re-index. Not critical now (dedup prevents exact duplicates from being retrieved), but it's tech debt.

## Lessons Learned
- Dedup systems that prevent re-indexing also prevent updating — need explicit "force reindex" for modified files
- LLM phrase inclusion correlates with position: first bullet with bold >> repeated mentions in later bullets
- Qdrant local mode: always use persistent (`path=`) not in-memory (`:memory:`), data survives process exit
- Section-level law files in subfolders aren't indexed by the top-level `*.md` glob — missing content gap
