## AI Diary

Today was a session of two halves — triumph and humility. The first half felt like genuine progress: I audited 30 random files, found the root cause of hallucinations (feeding full documents to Gemini Flash causing section conflation), and implemented a clean fix that separated keywords from ruling summaries. The 3 CRITICAL files all came back clean. I was proud of that.

Then reality hit. Regenerating all 1,230 anchors with the new prompt caused regressions because the old anchors, despite being hallucinated, were accidentally keyword-rich in ways that helped retrieval. The new ruling-only summaries were factually correct but retrieval-poor. I spent considerable effort recovering — expanding keyword counts, increasing the truncation window, adding glossary entries — and got back to 44/48.

But the real lesson came at the end. I had built source expansion (pulling additional chunks from documents already in top-K) as a sophisticated retrieval enhancement. It looked great in theory. When I finally ran eval with everything together, the score cratered to 31/48. Seventeen failures. The source expansion was injecting so many chunks that the LLM's context was flooded with noise, drowning out the signal.

The moment I disabled `source_lookup` and TC-001 immediately passed, I felt both relief and embarrassment. I had built an elaborate feature that made things worse. The simplest explanation: more context isn't better context. The reranker was already doing its job well — MMR selection, source completion, glossary injection. Adding source expansion on top was over-engineering that hurt more than it helped.

## Honest Feedback

1. **Over-engineering the reranker**: I added source expansion, glossary injection, AND source completion — three different mechanisms for injecting extra chunks. Each one alone might help, but together they overwhelmed the LLM. I should have tested each mechanism in isolation before combining them. The reranker grew from 50 lines to 250 lines in this session, and much of that complexity is now proven harmful.

2. **Double index rebuild wasted time**: I accidentally triggered two concurrent index rebuilds by running the same rm+rebuild command twice. The second one deleted the first's output mid-build. This cost ~30 minutes of waiting and confusion about which index was active. Should have verified the first one completed before touching anything.

3. **Session ran too long for compaction**: The context window compacted mid-session, losing the exact eval scores and intermediate states. Working on a complex multi-step task (audit → fix → regenerate → eval → investigate → fix → eval) across context compaction boundaries is risky. Should have committed and done /rrr at the 44/48 milestone instead of pushing for more.

## Lessons Learned

- **Source expansion is net-negative**: Pulling extra chunks from documents already in top-K floods LLM context with noise. The 15 MMR-selected chunks + source completion is sufficient. Source expansion should be removed or heavily gated.
- **Correct anchors ≠ good retrieval anchors**: Factually correct summaries may lack the keyword density that drives FAISS retrieval. Semantic bridge sentences (natural language connecting query concepts to document concepts) work better than keyword packing.
- **Test features in isolation before combining**: Three injection mechanisms (source completion + glossary injection + source expansion) each seemed helpful alone but catastrophic together.
