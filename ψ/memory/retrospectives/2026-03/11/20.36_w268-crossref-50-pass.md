## AI Diary

Today was a session about precision engineering — making one specific document appear in one specific answer. The user knew exactly what they wanted: "ทำยังไงให้ตอบคำถามนี้ด้วย ว268." Clear, direct, no ambiguity.

The interesting puzzle was the pipeline dynamics. ว268 exists in FAISS top-80 (positions #18, #24, #28, etc.) but MMR consistently filters it out because it's semantically redundant with ว52 and ว647 — they all discuss penalty reduction. This is MMR working *correctly* from a diversity standpoint, but *incorrectly* from a legal standpoint where each circular letter carries its own authority.

My first cross-ref attempt in ว52 failed because I assumed ว52 would be highly ranked for TC-050. It wasn't — ว647 was the consistent #1. Lesson: verify which document actually gets retrieved before injecting. The second attempt in ว647 worked, and with enriched text (mentioning "เหตุสุดวิสัยภายหลังครบกำหนด" specifically), the LLM now explicitly names ว268 in its answer.

The TC-003 regression was unexpected but instructive. Adding ~50 words of cross-ref text to ว647 changed its chunk boundaries just enough to shift what the LLM prioritizes. The "ผลิตภายในประเทศ" content was still in the context (FAISS #18, source 20140 cited) but the LLM chose not to mention it. A rescue phrase fixed it deterministically. We're now at 3 rescue phrases — still well within the "acceptable" range (<10).

I feel the weight of accumulating post-processing rules. Each one is justified, each one works, but the system is slowly becoming a patchwork of special cases. The question is whether there's a more elegant architectural solution, or whether this is just the nature of RAG systems dealing with domain-specific requirements.

## Honest Feedback

**Friction 1: Index rebuild cycle time.** Each rebuild takes ~7-8 minutes. When testing cross-ref placement, I needed 3 rebuilds (ว52 attempt, ว647 attempt, ว647 enhanced text). That's 20+ minutes of waiting. A partial/incremental rebuild for single-document changes would dramatically speed up iteration. The full delete-and-rebuild approach is safe but painfully slow for iterative development.

**Friction 2: Cross-ref placement is trial-and-error.** I had no way to predict that ว52 wouldn't work but ว647 would, without actually running the pipeline. A diagnostic mode that shows "for query X, these are the final chunks sent to the LLM" would eliminate guesswork. Currently I have to run FAISS search manually, then mentally simulate MMR, then guess.

**Friction 3: Context window pressure from continuation.** This session was a continuation from a previous one that ran out of context. The summary captured key facts but lost nuance — I had to re-discover some things (like FAISSStore constructor taking no args). Continuation summaries should include API signatures of key classes used.

## Lessons Learned

- Cross-ref injection must target the **consistently top-ranked** document, not just any relevant one
- Adding text to a large document changes chunk boundaries, potentially causing regressions in unrelated test cases
- Rescue phrases scale linearly — 3 is fine, 10 would need rethinking
- MMR filters out legally distinct but semantically similar documents — a fundamental tension in legal RAG
