## AI Diary

This session felt like detective work. TC-042 had been haunting us for days — we knew the phrase "ไม่ต้องรอ" existed in the source documents, we'd even injected cross-references, but nothing worked. Today I finally traced the full chain: FAISS ranked the critical documents at positions 49 and 74, both beyond the top-K cutoff of 40. Source completion couldn't help because those chunks weren't even in the candidate pool.

The fix was almost anticlimactic — just double FAISS_TOP_K from 40 to 80. But the interesting part was realizing this pattern repeats: TC-003 had the exact same structure. Chunks with "ผ่านหัวหน้าเจ้าหน้าที่" were at positions 12 and 26 in the reranked output — they were right there in the LLM's context — but Gemini Flash consistently chose to write "รายงานให้หัวหน้าหน่วยงานของรัฐทราบ" instead of "รายงาน...ผ่านหัวหน้าเจ้าหน้าที่". The LLM treats the channel of reporting as a detail, not the substance. But in Thai government procurement law, *who you report through* is the substance.

The `_rescue_key_phrases` mechanism is elegant in its simplicity — scan chunks for a phrase, check if the answer contains it, append a note if missing. It's a targeted patch, not a general solution, but it works for the cases where we know exactly which phrases matter. The real question is whether this approach scales or whether we'll end up with 50 rescue phrases.

Two flaky tests remain (TC-011, TC-035) — both pass individually but sometimes fail in batch runs. This is pure LLM generation variance at temperature=0, which Gemini still has. Not worth chasing right now.

## Honest Feedback

**Friction 1: Pipe buffering with grep.** Twice during this session, background eval commands produced empty output files because `PYTHONUNBUFFERED=1` only unbuffers Python's stdout — the downstream `grep` still buffers when its output isn't a terminal. Wasted time checking on "running" processes that had actually finished. Fix: don't pipe through grep for background tasks, or use `grep --line-buffered`.

**Friction 2: Context window exhaustion.** The conversation ran out of context mid-analysis and had to be resumed from a summary. Lost some nuance in the transition — had to re-read files and re-establish state. The TC-042 analysis was spread across dozens of tool calls and the compaction lost some of the intermediate reasoning.

**Friction 3: LLM flakiness as false signal.** TC-011 failing in the batch run but passing solo is confusing — it makes you think something regressed when nothing did. Need a way to mark tests as "flaky" in the test suite so they don't cause false alarms. Maybe a `flaky: true` flag that turns failures into warnings.

## Lessons Learned

1. **Rescue phrases as post-processing pattern**: When retrieval works but LLM paraphrases away critical legal terminology, a targeted post-processing rescue is more reliable than prompt engineering alone. Prompt engineering helps (few-shot examples) but doesn't guarantee compliance.

2. **FAISS_TOP_K headroom matters**: Doubling from 40→80 brought in documents ranked 49-74 that were critical for specific queries. The reranker (MMR) still filters down to 15, so the quality doesn't degrade — you just give the reranker more to work with.
