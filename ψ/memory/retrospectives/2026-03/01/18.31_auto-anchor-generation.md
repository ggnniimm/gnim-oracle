## Honest Feedback

**Friction 1: Waiting game.** The 52-minute batch run was unavoidable but made the session feel slow. The 1 req/sec rate limit is conservative — could potentially run 2-3x faster with the actual API limits, but the risk of more 429s isn't worth it. A progress bar or ETA would have been nice in the script output (just used log lines).

**Friction 2: No retry logic in the script.** The 2 failures required manual retries with `--file`. Should have built automatic retry with backoff into the script — a simple `for attempt in range(3)` wrapper around the Gemini call would have made it truly fire-and-forget. Minor gap but worth noting for production quality.

**Friction 3: Anchor quality is unchecked.** We verified one dry-run looked good and trusted the rest. No systematic quality check across all 970 anchors. Some files might have poor content (very short documents, scan artifacts) that produce low-quality anchors. A spot-check of 10-20 random anchors would add confidence.

## Lessons Learned

- **Simple prompts work**: "15-20 keywords + 2-3 sentences, plain text" produced consistently good retrieval anchors across 970 diverse legal documents
- **Idempotency is essential**: The `has_anchor()` check made the script safe to re-run — skips already-processed files, so you never double-append
- **sys.path.insert pattern**: All pipeline scripts in this project use `sys.path.insert(0, str(Path(__file__).parent.parent))` to import from `src/` — must remember this for any new pipeline script
