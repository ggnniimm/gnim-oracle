## Honest Feedback

**Friction Point 1: Context overflow kills momentum.** This session started from a context-overflow continuation. The summary was good but I still had to re-discover things like `IndexManager(use_lightrag=False)` and the correct eval runner invocation. Resumption tax is real — probably 5-10 minutes of fumbling with imports and paths that I already knew in the previous context.

**Friction Point 2: Inline Python scripts vs eval runner environment.** The eval runner (`run_eval.py`) works fine because it handles the `sys.path.insert` and `IndexManager` setup correctly. But when I tried to replicate the same pipeline in an inline `-c` script, I hit `lightrag` import errors that the eval runner somehow avoids. Spent 3-4 tool calls figuring out `use_lightrag=False`. Should have just used the eval runner from the start.

**Friction Point 3: must_contain design is an art, not a science.** Every TC needs careful consideration: "Will the LLM reliably include this exact phrase?" "มาตรา 102" seemed safe but failed because the LLM prefers the ระเบียบ reference. "7 วัน" works because the number is fixed. "ประกาศเชิญชวนทั่วไป" works because it's a proper legal term. There's no systematic way to predict which phrases will be stable — it's trial and error.

## Lessons Learned

- Pre-contract topics (วิธีจัดซื้อ, วงเงิน, อุทธรณ์) pull from broad legal sources (พ.ร.บ., ระเบียบ, กฎกระทรวง) rather than specific ข้อหารือ — must_contain should use established legal terminology which is stable across LLM runs.
- When must_contain fails, prefer terms that appear directly in the source document's text, not derived legal references (ข้อ 182 in ระเบียบ is more stable than มาตรา 102 in พ.ร.บ. when the source is a ระเบียบ-based ข้อหารือ).
