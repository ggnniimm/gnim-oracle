## Honest Feedback

1. **Plan estimates were off** — The plan said ข้อ 55 should be ~8 วรรค and ข้อ 56 should be 2. Actual results were 5 and 3. The estimates were made without deeply understanding the legal structure. Lesson: approximate is fine for direction, but don't treat estimates as test assertions.

2. **Continuation word list is fragile** — `ตาม|แต่|และ|หรือ|เว้นแต่|โดย|ซึ่ง|ที่|แห่ง|เพื่อ` is a heuristic. Some of these (especially แต่, ที่) could legitimately start new วรรค. The current approach works for the cases we've seen, but may need refinement as we process more laws.

3. **No unit tests** — All verification was manual (grep total_paragraphs, read MD files). A proper test suite with known-good วรรค splits would catch regressions and make future changes safer. Should be a priority before the next round of splitting changes.

## Lessons Learned

- Post-processing is more reliable than prompt engineering for deterministic rules (list item merging)
- Thai legal structure is hierarchical (ข้อ → วรรค → อนุข้อ → วรรคย่อย) — flat paragraph lists lose information
- Accept single results from AI: discarding valid single-paragraph Gemini output caused unnecessary fallbacks
