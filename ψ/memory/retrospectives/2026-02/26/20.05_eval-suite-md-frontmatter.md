## Honest Feedback

**Friction 1: must_contain design requires reading the actual answer.** The natural instinct is to write must_contain phrases from legal memory ("the answer should say ผู้มีอำนาจสั่งซื้อ"). But LLMs use the phrasing from the source documents, not from my mental model. The correct workflow: run the query, read the full answer, then extract phrases that consistently appear. I didn't do this initially for TC-004 and wasted a debugging cycle.

**Friction 2: LLM non-determinism makes eval fragile at temperature=0.1.** TC-004 failed on one run, passed on two more. TC-005 showed the same pattern earlier. An eval suite that sometimes passes and sometimes fails is not a reliable benchmark. Options: run 3× and require 2/3 majority; lower temperature to 0.0; use retrieval-only checks for the most volatile cases. For now it's "good enough" but this is technical debt.

**Friction 3: 27 new chunks from re-index — where did they come from?** I said "the md_loader already handled hybrid format so re-indexing shouldn't add anything." But 27 chunks were new. I don't know which MD files they came from or why they weren't indexed before. This is a gap in understanding — I should have investigated before closing the session. Mystery chunks in an index are a potential source of quality issues.

---

## Lessons Learned

1. **Read the LLM's actual output before deciding the eval is wrong**: When must_contain fails, read the full answer (not just 300-char snippet) before assuming the pipeline is broken. The answer might be correct but using different phrasing than expected.

2. **Check the code before answering "does this affect RAG quality?"**: md_loader.py already had `_HYBRID_FRONTMATTER_RE`. Reading it first saved time and gave an accurate answer. Pattern: always read relevant code before making quality claims.

3. **must_contain phrases must be substrings of what LLM actually produces**: "ผู้มีอำนาจสั่งซื้อ" ≠ "ผู้มีอำนาจอนุมัติสั่งซื้อหรือสั่งจ้าง". Thai legal phrases often have additional qualifiers ("อนุมัติ", "หรือ", "สั่งจ้าง") that break naive substring matching. Extract phrases from actual LLM output.
