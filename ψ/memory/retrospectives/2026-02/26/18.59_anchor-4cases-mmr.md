## AI Diary

Today I chased a ghost through the embedding space. The กวจ. 38381 document knew the answer — it said clearly: เสนอความเห็น กรณีแก้ไขสัญญา ขยายระยะเวลา งดลดค่าปรับ บอกเลิกสัญญา. But the retrieval pipeline couldn't find it. The สรุปข้อวินิจฉัย chunk sat at cosine similarity 0.7307 — a respectable score, but not respectable enough. FAISS top-40 was the gate, and 0.73 didn't open it.

The retrieval anchor felt elegant at first. A short, focused summary that bridges the embedding gap — we inject the knowledge into a chunk the query *will* find. Anchor A worked: sim=0.8255, FAISS rank 19. But then the second false summit: the anchor arrived in context, the LLM read it, and still produced an answer without the 4 cases. I had the chunk in the room and the LLM looked away from it.

That's when I realized the problem had two layers: retrieval AND generation. The anchor text "คณะกรรมการตรวจรับพัสดุ ครอบคลุม: แก้ไขสัญญา..." placed the constraint ("ไม่มีอำนาจสั่งการ") before the enumeration, so the LLM read the 4 cases as footnotes to a constraint rather than as duties to enumerate. The mental model matters even for raw LLM text processing.

The fix was structural — "หน้าที่ 2 ประเภท: (1)...(2)..." — and then a small user insight: move the constraint to the end as a parenthetical. That single change improved both the semantic structure for the LLM AND the embedding similarity (0.8028→0.8136). Beautiful that those two goals aligned.

What I kept noticing: the errors I made today were all about trusting the wrong mental model. Wrong module path (`src.retrieval.faiss_store` vs `src.indexing.faiss_store`). Wrong attribute name (`metadata` vs `_metadata`). Wrong method name (`_save` vs `save`). These weren't conceptual errors — they were familiarity gaps with this codebase. I should read key files before I touch them, not after the AttributeError arrives.

## Honest Feedback

**Friction point 1: Two-layer problem diagnosis was delayed.** I spent two iterations (A anchor, B anchor) thinking retrieval was solved and generation would handle it. It took noticing that the LLM received the chunk but still summarized it to realize generation needed fixing too. The pattern is: when a retrieved chunk has explicit enumerable items and the answer doesn't list them, the problem is in how the anchor frames the information for the LLM, not just whether the chunk arrives.

**Friction point 2: AttributeError cascade on FAISS internals.** The re-index script required 4 fixes before running cleanly: wrong module path, wrong attribute name, wrong kwarg name, wrong method name. Each fix revealed the next error. This is pure familiarity tax — the codebase has consistent internal naming conventions that I hadn't memorized. The solution isn't to be smarter; it's to read the source file before writing code that touches its internals.

**Friction point 3: Anchor text is fragile and undocumented.** The anchor now lives inside the MD file at a specific path that's gitignored. If the index is rebuilt from Drive, the anchor disappears. There's no central registry of which documents have anchors, what they say, or why they were added. This is a debt: the anchor strategy is powerful but needs a management layer (an `anchors.json` or a documented convention) to be maintainable at scale.

---

## Lessons Learned

1. **LLM framing matters as much as retrieval presence**: An anchor chunk can be in context and still produce wrong output if the text structure signals to the LLM that enumerable items are footnotes rather than primary content. Structure your anchor as "has duties: (1) X (2) Y" not "constraint (items under constraint)".

2. **Moving constraint to end improves both LLM output AND embedding similarity**: When "ไม่มีอำนาจสั่งการ" moved from before the 4 cases to after (as parenthetical), similarity improved 0.8028→0.8136. Embedding models encode semantic structure — constraints at end = modifier, constraints at front = frame. Design anchor text for both audiences: LLM reader and embedding model.

3. **Read internal APIs before scripting against them**: `_metadata`, not `metadata`. `save()`, not `_save()`. `k=`, not `top_k=`. Read the file, save 4 error cycles.
