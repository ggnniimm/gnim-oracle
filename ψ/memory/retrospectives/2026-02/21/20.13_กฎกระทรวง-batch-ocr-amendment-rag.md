## Honest Feedback

**3 friction points:**

1. **Signature block regex ต้องรู้ keyword ล่วงหน้า** — pattern `ให้ไว้ ณ วัน` เราไม่รู้จนกว่า กฎกระทรวง ฉบับแรกจะผิด ถ้า document types อื่นมี signature keywords ที่ต่างออกไปอีก จะต้องมาแก้ regex ซ้ำ ควรพิจารณา approach ที่ยืดหยุ่นกว่านี้ เช่น scan from-bottom-up ไปเจอ 3-5 บรรทัดสุดท้ายที่ไม่ใช่ legal text

2. **Batch OCR ไม่มี dry-run ที่ปลอดภัย** — ตอน dry-run ครั้งแรก API key ไม่ได้ถูก pass ไป ทำให้ cache ถูก write ด้วย fallback (blank-line split) แทน Gemini split ต้องลบ cache ทิ้งแล้วรันใหม่ควรมี flag `--no-write-cache` สำหรับ true dry-run หรืออย่างน้อย warn ถ้า Gemini key ไม่มีแล้วยังจะเขียน cache

3. **Amendment chain ยังไม่ fully solved** — Option C แก้ได้ระดับ LLM behavior แต่ FAISS ยังดึง chunks จากทุกฉบับ (เก่า+ใหม่) ขึ้นมาด้วย ถ้า context window ถูกกินด้วยฉบับเก่าเยอะ ความแม่นยำจะลด Option B (status metadata + retrieval filter) จะ solve ได้ cleanly กว่า แต่ต้องการ effort มากกว่า

## Lessons Learned

1. กฎกระทรวงใช้ `ให้ไว้ ณ วันที่` ส่วน พ.ร.บ. ใช้ `ประกาศ ณ วัน` — regex `_SIGNATURE_BLOCK_RE` ต้องรองรับทั้งสอง
2. `law_year_be` ใน FAISS metadata คือ key ที่ทำให้ amendment-awareness ทำได้ด้วย prompt ไม่ต้อง re-pipeline
3. Option C (prompt engineering) เป็น MVP ที่ดีสำหรับ amendment handling — เร็ว ไม่ต้อง re-index แต่มี ceiling ที่ retrieval layer
