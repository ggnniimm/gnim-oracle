## AI Diary

I came into this session expecting a quiet one. Six issues open, but three were already resolved — just forgotten to close. That kind of housekeeping is almost satisfying: you realize more is done than it looked.

Issue #4 was the real work. The symptom was obvious: มาตรา 4 had 21 วรรค when it should have 1. Each definition `"คำ" หมายความว่า ...` was being treated as an independent paragraph. The fix seemed straightforward — detect this pattern, merge it like a list item.

The first attempt failed silently. Tests passed, but the actual output didn't change. That's the uncomfortable kind of failure — no error, just wrong results. The debugging step that cracked it: printing hex values of the first characters. `0x201c`. Not a regular double quote. A Unicode left quotation mark. The document uses typographic curly quotes `"..."`, not ASCII `"..."`. My regex used `"` and missed everything.

Once that clicked, there was a second edge case: `"ระบบข้อมูลสินค้า" (Electronic Catalog : e - catalog) หมายความว่า` — a parenthetical between the closing quote and `หมายความว่า`. The first fixed regex required the Thai word immediately after the quote. A small `.{0,60}?` gap solved it cleanly without opening the door to false positives.

What I find most satisfying about this kind of work is the precision required. Thai legal text has structure — consistent, formal, deliberate. Once you understand the grammar of the document, the patterns reveal themselves. Definition sections always use `"X" หมายความว่า`. Always curly quotes. Always this phrase. The code just needed to learn that grammar.

## Honest Feedback

Three friction points this session:

**1. Silent failures during regeneration** — The `regenerate_sections.py --resplit` script ran and reported sections changed, but the specific files we were checking hadn't updated yet. Multiple runs were needed before it was clear whether the fix was working. The script needs a `--show-changes` option that lists which specific sections changed (before/after count), not just a total.

**2. Quote character invisibility** — Curly quotes (`\u201c\u201d`) look identical to ASCII quotes in most editors and terminal output. There's no visual indicator that these are different characters. A helper debug function that prints character codepoints would have saved 10 minutes of confusion.

**3. Background task timing** — Three background task notifications arrived after the main work was done. Because they ran out-of-sync, I had to cross-check which output belonged to which code version. Better to run regeneration inline (non-background) when the result is needed immediately for verification.

---

## Lessons Learned

- Thai legal PDF text uses Unicode curly quotes `\u201c` / `\u201d`, not ASCII `"` — always check `hex(ord(c))` when regex doesn't match visually identical text
- `_has_list_markers_ahead` must include all "list-like" patterns (definition items, not just `(๑)(ก)`) for look-ahead to work correctly
- When testing a fix, use `python3 -c "... _post_merge_paragraphs(actual_cache_data) ..."` to verify against real data, not just synthetic test fixtures
