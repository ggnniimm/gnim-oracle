## AI Diary

This session had a satisfying rhythm — each problem led cleanly to the next fix, with no real dead ends.

The category reclassification was Ming's idea and a good one. The distinction between "ข้อหารือ กวจ." (case-by-case rulings), "ข้อหารือแนวทางปฏิบัติ กวจ." (guideline inquiries), and "ซ้อมความเข้าใจ กวจ." (authoritative circulars) matters for query filtering. The 56 "แนวทางปฏิบัติ" files were all "ข้อหารือแนวทางปฏิบัติ" — still an inquiry format — so "ข้อหารือแนวทางปฏิบัติ กวจ." was the right middle ground. Preserves the inquiry nature while being specific.

The Drive shared folder bug was a classic. `list_files()` had been working fine for My Drive folders all along — the original CGD folder must have been owned by the service account or shared in a standard way. CGD2 was either a shared drive or in a different user's Drive — `supportsAllDrives=True` is the magic flag that makes it visible. Two lines of code, fixed in two minutes, unblocked 170 files. The dry run cadence (dry-run first, verify count, then real run) saved us from wasting OCR calls on a silent failure.

170 files, 1.5 hours, 146 indexed on first pass. The 24 failures split cleanly: one file with confidence=0%, the rest with empty metadata in frontmatter. The empty-metadata files weren't bad OCR — `ว54.pdf` actually had perfect content inside its cache. The issue was something subtle in the frontmatter extraction: these files had their metadata available in `text` (which I confirmed by reading the cache), but my initial check was looking at wrong top-level keys. I caught and corrected that quickly.

The re-OCR pipeline I improvised on the fly was clean: identify bad file IDs → remove chunks from FAISS/BM25 → clear from dedup DB → delete cache → retry. Three separate stores to keep in sync (FAISS metadata, BM25, dedup.db) — and I got the table name wrong the first time (indexed vs indexed_chunks). Small friction.

`กวจ_ว48` at 9.3 MB failing once then succeeding on retry is typical of Gemini's File API — large files sometimes time out on upload or classification but succeed on retry. Worth noting for future large-file handling.

## Honest Feedback

**Friction 1: Wrong quality check logic (first attempt).** My initial quality check looked for `ref_number`, `date`, `title` as top-level keys in the OCR cache JSON. But those fields are embedded inside the `text` field's YAML frontmatter, not at the top level. The cache structure is `{text, doc_type, category, confidence, file_id, filename}`. This produced a false alarm: all 146 files appeared to have missing metadata when actually 122 were fine. I should have read one cache file first before writing the check logic. I did check the structure immediately after and corrected course, but it wasted a round of analysis.

**Friction 2: dedup.db table name mismatch.** I guessed the table was called `indexed` but it was `indexed_chunks`. This caused a traceback in the cleanup script. I recovered by querying `sqlite_master` for the real table name. Minor, but it reflects that I don't have the dedup schema memorized — worth adding to memory.

**Friction 3: FAISS vector count vs BM25 count diverging.** After re-OCR, FAISS had 14,865 vectors but BM25 had 14,483 docs. The gap (382) is the bad chunks I removed from BM25 but couldn't remove from FAISS (FAISS has no delete API). The bad chunks remain in FAISS with empty metadata — they'll score poorly in reranking since they have no ref_number/date/topic. Functionally acceptable but architecturally awkward. A proper solution would be FAISS with delete support (HNSW with deletion, or periodic rebuild).

## Lessons Learned

1. **`supportsAllDrives=True` + `includeItemsFromAllDrives=True`** required in ALL Drive API list calls to see shared folders outside My Drive
2. **OCR cache structure**: top-level keys are `{text, doc_type, category, confidence, file_id, filename}` — metadata fields are inside `text` as YAML frontmatter
3. **dedup.db table name**: `indexed_chunks` (not `indexed`)
4. **Large file retry pattern**: Gemini File API sometimes fails on first upload for files >5 MB — retry usually succeeds
5. **Category granularity matters**: `ข้อหารือแนวทางปฏิบัติ กวจ.` vs `ข้อหารือ กวจ.` vs `ซ้อมความเข้าใจ กวจ.` — meaningful distinction for query filtering
