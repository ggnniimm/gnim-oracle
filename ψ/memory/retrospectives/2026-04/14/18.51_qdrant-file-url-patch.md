ผมรู้ว่ามี Drive ID remapping project ที่ verify แล้ว แต่กลับใช้ xlsx (ที่ไม่ได้ update พร้อมกัน) เป็น source โดยไม่ cross-check กับ MD files ก่อน การ cross-check 10 แถวใน 1 นาทีจะช่วยได้มาก

รัน patch 55K chunks บน production server โดยไม่มีการ backup Qdrant snapshot ก่อน ถ้า patch ผิดพลาดรุนแรงกว่านี้ recovery จะยากมาก ควร snapshot ก่อนทุกครั้ง

**3. ถาม Ming แทนที่จะทดสอบเอง**
เมื่อ Ming บอกว่า "ลองทำดูแล้วจะรู้ ทำแล้วยัง" — ผมควรหาวิธีทดสอบเองแทนที่จะถาม Ming ซ้ำๆ ว่า link ยังเสียอยู่ไหม

## Lessons Learned

- **MD frontmatter คือ source of truth สำหรับ Drive file_id** — xlsx เป็น inventory tracking ที่อาจ stale; MD files คือสิ่งที่ verified จริง
- **cross-check sources ก่อน patch production เสมอ** — `md_id != xlsx_id` check ใช้เวลา 10 วินาที แต่ประหยัดเวลาได้ชั่วโมง
- **Qdrant snapshot ก่อน mass patch** — `POST /collections/{name}/snapshots`
