## Honest Feedback

**1. Assumption ว่า "already patched" โดยไม่ verify Qdrant**
ตอนที่ scan หาไฟล์ missing เราดูแค่ว่า MD file มี file_id ถูกไหม แต่ไม่ได้ verify ว่า Qdrant จริงๆ ถูกด้วย มีช่องว่างระหว่าง MD state กับ Qdrant state ที่ต้องตรวจแยกกัน ควรมี verify step ที่เช็คทั้งสองแหล่งเสมอ

**2. `patch_from_drive.py` ไม่ใช้ env var**
Script เขียน QDRANT_URL เป็น hardcode constant ไม่ใช่ `os.environ.get()` ทั้งที่ docstring บอกว่าใช้ env var ได้ ทำให้ต้อง debug หา bug นี้ตอน deploy production เป็นเรื่องที่ควรทดสอบ script บน server path ก่อน ship

**3. `-2` suffix files ไม่มี logic อัตโนมัติ**
ไฟล์ที่มี `-2` suffix (split PDF) ไม่ได้รับการ handle โดย `patch_from_drive.py` เลย เพราะ Drive ไม่มี entry ที่ชื่อลงท้าย `-2` ต้องทำ manual ทุกครั้ง ควร add logic ใน script ที่ถ้า match ไม่ได้ ให้ลอง strip `-N` suffix แล้ว match กับ base file

## Lessons Learned

1. **Qdrant payload ≠ MD file state** — ต้อง verify ทั้งสองแหล่งแยกกัน เพราะ pipeline patch อาจพลาดบางไฟล์ที่ชื่อ match ไม่ได้
2. **`-N` suffix files ต้องการ special handling** — ไฟล์ที่เป็น page 2+ ของ PDF เดิม ควร fallback ไปหา base doc ID
3. **Script env var ต้อง `os.environ.get()`** — ไม่ใช่แค่ docstring ที่บอกว่าใช้ได้
