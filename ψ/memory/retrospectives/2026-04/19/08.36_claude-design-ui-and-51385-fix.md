## AI Diary

Two very different things happened today, and both taught me something.

The UI work was creative and demanding in a different way than debugging. Claude Design is elegant — IBM Plex fonts, the warm ochre accents against the dark indigo sidebar, the Q/A card layout. But porting it to Streamlit felt like translating poetry between languages. The spirit is preserved but the structure fights you at every turn. `st.markdown(unsafe_allow_html=True)` is both the workaround and the limitation — I could inject HTML but couldn't add `<link>` tags cleanly. The IBM Plex fonts needed a `<style>` import in the very first CSS block.

The sticky profile card was the most satisfying solve. `position: fixed` would have been brittle — hardcoding sidebar width. The CSS `:has()` approach — making the stVerticalBlock a flex column and pushing the `.profile-card` wrapper down with `margin-top: auto` — feels right. It works WITH Streamlit's DOM structure instead of fighting it.

Then the 51385 hallucination. That was humbling in a different way. My first fix was directionally correct but diagnostically shallow. I added "ก่อนตรวจรับ ไม่ใช่หลัง" — which addresses direction confusion — but missed the category confusion. The LLM was putting 51385 in the wrong bucket ("exception to post-inspection rule") rather than just misreading its direction. When Ming asked "ทำไมยังถูกอ้างอิง", I had to look again and realize I'd solved the wrong problem.

The second fix was surgical: "อย่าอ้างหนังสือฉบับนี้เป็นหลักฐานว่าแก้ไขสัญญาหลังตรวจรับงานงวดสุดท้ายได้". It works because the RAG context is read directly by the LLM — a negative instruction embedded in the retrieved chunk becomes a direct constraint. Unusual technique. Worth documenting.

Deploying to production and verifying TC-008 there felt complete in a way that local tests don't. Ming's reminder about making post-deploy testing a habit is exactly right — local and production aren't the same environment.

## Honest Feedback

**Friction 1: First 51385 fix was diagnostically insufficient.** I identified direction confusion but not category confusion. These are different: direction confusion = LLM reads the document correctly but attributes the wrong direction. Category confusion = LLM puts the document in the wrong semantic bucket entirely. I should have asked "why does the LLM associate this document with the exception case?" rather than just "how do I make it clearer that inspection hasn't happened?" The second question led to a symptom fix; the first question would have led to the root fix immediately. Required a second round because I diagnosed at the wrong level.

**Friction 2: Streamlit CSS environment needed early in the session.** The `.streamlit/config.toml` with `base=light` was discovered after the dark theme was fighting the sidebar CSS. This should have been set at the very start of any Streamlit CSS customization — light base is the prerequisite for custom dark-sidebar injection. I had to debug the symptom ("CSS not applying even with !important") before finding the cause. A quick check of existing Streamlit config at session start would have prevented this.

**Friction 3: Production path uncertainty cost time.** When deploying to production, I had to `find / -name '*.py'` inside the container to locate run_eval.py. The correct path (`/app/pipeline/run_eval.py`) wasn't in memory. The rsync path (`/app/thai-legal-rag/data/md_backup/`) also had to be discovered. These are known facts that decayed. Should be pinned somewhere persistent and verified on the first successful deploy so future sessions don't repeat the discovery.

## Lessons Learned

1. **RAG negative annotation**: When a document keeps being miscited for claim X, add explicit "อย่าอ้างหนังสือฉบับนี้เป็นหลักฐานว่า X" to บทสรุปสำหรับสืบค้น. The retrieved chunk is read directly by the LLM — negative instructions in context work.

2. **Category confusion ≠ direction confusion**: Two distinct failure modes. Direction confusion: LLM misreads which direction the document points. Category confusion: LLM associates the document with the wrong semantic bucket. The fix for category confusion must explicitly name the wrong category: "ไม่ใช่กรณี X ที่อาจแก้ไขหลังตรวจรับได้."

3. **Always test on production after deploy**: Not just local. Ming's instruction: "ทำเป็นนิสัยเลย". The eval command: `docker exec thai-legal-rag-app-1 python3 /app/pipeline/run_eval.py --id TC-XXX -v`

4. **CSS :has() for Streamlit sticky sidebar element**: `section[data-testid="stSidebar"] [data-testid="stVerticalBlock"] > div:has(.profile-card) { margin-top: auto !important; }` — targets the wrapper div that contains the profile card element. Requires stVerticalBlock to be `display: flex; flex-direction: column; height: 100%`.

5. **`.streamlit/config.toml` base=light is prerequisite for sidebar CSS**: Must be set before any dark-sidebar CSS injection, or Streamlit's dark theme wins even with !important.
