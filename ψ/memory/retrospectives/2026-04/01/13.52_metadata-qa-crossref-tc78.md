## Honest Feedback

1. **Gemini timeout instability**: 4-5 TCs fail each full eval run due to Gemini API timeouts (504 DEADLINE_EXCEEDED), not actual answer quality issues. This makes the eval signal noisy — every run requires re-running failures to confirm they're flaky. We need either retry logic in the eval runner or a way to distinguish timeout failures from content failures.

2. **Cross-ref placement requires trial and error**: Adding cross-ref to the source document (อ.480/2557) didn't work because it wasn't getting retrieved. Had to check top-ranked chunks first, then add cross-ref to the doc that IS retrieved (กวจ 46043). This is documented in learnings but still requires manual verification each time.

3. **Full eval takes too long**: 78 TCs × ~20-30s each = 30+ minutes per run, and that's when Gemini doesn't timeout. With timeouts some TCs take 140-245s. Would benefit from parallel execution or caching of retrieval results.

## Lessons Learned
- Old Thai procurement regulations (ระเบียบพัสดุ) and new พ.ร.บ. share the same legal principles — court judgments under old law are valid examples for new law provisions
- Cross-ref must go in BOTH the source document AND the top-ranked document to ensure retrieval
- Running RAG queries interactively (not just eval) reveals answer quality nuances that pass/fail can't capture
