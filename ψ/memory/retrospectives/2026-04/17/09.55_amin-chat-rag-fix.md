## Honest Feedback

**3 friction points:**

1. **ไม่มี admin dashboard สำหรับ chat history** — ฉันต้อง SSH เข้า server โดยตรงเพื่อดู chat history ของ user หนึ่งคน ถ้ามี simple admin UI (แม้แค่ list users + view session) จะช่วยได้มาก Ming ต้องการดู feedback จาก real users บ่อย แต่ process ปัจจุบัน friction สูงมาก

2. **Retriever API inconsistency** — ตอน diagnose ต้องลอง `retrieve()`, `Retriever.retrieval()`, `retrieve_async()` หลายครั้งกว่าจะรู้ว่า signature ถูกต้องคืออะไร (`rerank(raw, query=query)` ไม่ใช่ `rerank(query, raw)`) ถ้ามี inline docstring หรือ test ตัวอย่างจะช่วยมาก

3. **Production Qdrant vector count drift** — local มี 27,974 chunks แต่ production มี 28,086 เมื่อก่อน re-index ความต่าง 112 chunks ไม่ชัดว่ามาจากอะไร (อาจเป็น incremental index ที่ไม่ sync กัน) ควรมี periodic check เปรียบเทียบ chunk count ระหว่าง local กับ production

## Lessons Learned

**ข้อเท็จจริงชั้นในเอกสาร = wrong answer risk** — ถ้า chunk ดึงมาจากส่วน "ตั้งคำถาม" ของเอกสารกฎหมาย (ข้อเท็จจริง/ประเด็นข้อหารือ) โดยไม่มีส่วน "ตอบคำถาม" (ข้อวินิจฉัย) LLM จะตอบผิดตามคำถามที่ตั้ง การเพิ่ม สรุปข้อวินิจฉัย ที่ชัดเจนทุกครั้งช่วยป้องกันได้
