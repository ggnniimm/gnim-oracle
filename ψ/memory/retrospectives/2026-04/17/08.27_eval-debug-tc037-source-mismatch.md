## AI Diary

The real lesson from this session isn't about TC-037 — it's about the shape of the investigation. I went from "retrieval failure?" to "doc not in Qdrant?" to "dedup says it's there?" to "source_name mismatch." Each step narrowed the hypothesis. What I didn't do well: I checked Qdrant by scrolling for an exact `.md` source_name match. The doc was actually there all along — indexed months ago under `.pdf` source_name. My query was looking in the wrong place. The force-reindex output was the reveal: "Deleted 62 vectors (source_name='...PDPA.pdf')" — that `.pdf` suffix is the smoking gun.

This is a subtle pipeline issue: the indexer stores `source_name` as the filename of the original PDF, but the MD loader (used in newer re-indexes) stores it as the `.md` filename. When we ran force-reindex on this doc recently (probably when the pipeline was updated), old `.pdf` chunks got left orphaned while new `.md` chunks were supposed to replace them. But the `--force-reindex` during that update didn't trigger for this particular file — so we had 62 stale `.pdf` chunks in Qdrant and 0 `.md` chunks, causing retrieval to silently fall back to stale vectors that apparently didn't surface for this query.

The deeper question: how many other docs might have this same `.pdf`/`.md` split? I didn't check. I fixed the immediate failure but didn't audit the broader population. That's a known unknown I'm leaving on the table.

I also note that TC-037 passing after reindex doesn't mean the retrieval was better — the sources in the PASS result were still ว210, ว647, ว196 (not doc 12602). The 5M threshold that made it pass likely came from doc 12602's `.md` chunks now being available for BM25 keyword match (the exact string "5,000,000" in สรุปข้อวินิจฉัย). So the fix worked, but through BM25 not vector similarity. That's fine — hybrid search is designed exactly for this.

## Lessons Learned

1. **Source_name mismatch (.pdf vs .md) silently orphans Qdrant vectors** — when force-reindex runs on a doc, it deletes by source_name match. If the pipeline previously used `.pdf` as source_name and now uses `.md`, old chunks won't get deleted and new ones won't be recognized as duplicates. Always `--force-reindex` when changing source_name conventions, and verify with `curl Qdrant scroll` after.
2. **Debug retrieval gaps with fuzzy search first** — scrolling Qdrant by exact source_name fails if the name changed. Start with `MatchText(text='docid_fragment')` to find orphaned chunks, then trace the mismatch.
