## Honest Feedback

**Friction 1: I defended inference instead of seeking evidence.** When Ming asked if line 52 was original, I said "yes, because it's in ข้อวินิจฉัย section." That's structural reasoning, not source verification. Ming's pushback was correct — OCR files get edited regardless of which section they're in. I should have immediately proposed: "I can't verify without the PDF, let's check." Instead I stated it as fact, then had to backtrack.

**Friction 2: Google Drive MCP is unreliable in Claude Code CLI.** The connector shows as connected in Claude.ai settings but the MCP proxy returns "Server not found" in CLI sessions. This happened before today too. There's no clear signal to the user about when Drive MCP works vs not. A fallback should be established — either local token, or always-suggest the `! open URL` approach to have Ming verify directly.

**Friction 3: No simple PDF verification path from CLI.** When the question is "does this PDF contain this text?" — in a web browser I could navigate to Drive and read it. In CLI with read-only Chrome tier and no Chrome MCP, the only option is Ming doing it manually. For a RAG system that generates MD from PDFs, the ability to spot-check source PDFs quickly is important. The local token approach could work but token.json wasn't present. Should establish a reliable Drive API shortcut script.

## Lessons Learned

1. When a user asks "is this original or injected?" — never answer from structure alone. Go to source (PDF) immediately.
2. Google Drive MCP may be unreachable in Claude Code CLI sessions even when connected in Claude.ai — plan for this.
3. Suggest `! open URL` as fastest path for Ming to verify a Drive PDF directly.
