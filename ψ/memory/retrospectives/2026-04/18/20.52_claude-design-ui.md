## AI Diary

This was a satisfying session — implementing a full visual redesign in Streamlit from a Claude Design bundle. The challenge was bridging the gap between a pure HTML/CSS/JS prototype and Streamlit's constrained component model. Early on I injected a CSS block using oklch color notation for the design tokens, but oklch wasn't rendering correctly on all elements. I switched to hex colors for reliability.

The dark sidebar was initially showing as Streamlit's default dark theme rather than my intended indigo — the fix was creating `.streamlit/config.toml` with `base=light` first, then layering my CSS on top. Without that base config, Streamlit's own dark theme overrides body background even when you target `section[data-testid="stSidebar"]` with `!important`.

The stickiest problem was making the profile card stay at the bottom of the sidebar. Streamlit wraps every `st.markdown` in its own div chain, so I can't just add `margin-top: auto` to the content directly. The trick was making `stVerticalBlock` a flex column and using the modern CSS `:has(.profile-card)` selector to target its ancestor wrapper and apply `margin-top: auto` there. This works in Chrome (which is the production browser) but would fail in older browsers. An acceptable tradeoff for an experiment.

The Ming screenshot feedback workflow ("ทำไมไม่เหมือนอันนี้เลย", "ให้มันค้างอยู่ที่ล่างซ้าย", "ไม่เอาอันนี้") was fast and precise. Ming uses screenshots to show exact intent — this is more efficient than verbal descriptions for UI work. I should immediately zoom in on the referenced screenshot to understand the exact pixel-level detail rather than inferring.

The port-conflict issue (8501→8502→8503→8504) was friction from not properly killing old processes. I should always use `kill -9` and verify the port is free before launching.

## Honest Feedback

**Friction 1: Port management was messy.** Every restart attempt hit a port conflict (8501→8502→8503→8504). Each attempt added ~3min of wait time. The root cause: killing by port is unreliable when the process is still cleaning up. Better approach: kill by PID directly and wait for confirmation before starting on any port.

**Friction 2: Built a feature Ming didn't ask for.** The position-edit form in the gear popover was my own addition — Ming wanted a profile card that *shows* position, not necessarily one that lets you edit it via UI. Ming's response "ไม่เอาอันนี้" was clear rejection. I should have asked "ต้องการแก้ไขตำแหน่งจาก UI ด้วยไหม?" before building the form.

**Friction 3: Screenshot comparison took manual effort.** When Ming sent the reference screenshot, I had to mentally compare it with my implementation. I couldn't directly diff them. A better workflow would be to take a fresh screenshot immediately after opening the app and present both images side-by-side. Since Chrome is read-only tier, I had to ask Ming to navigate.

## Lessons Learned

1. `.streamlit/config.toml` `base=light` is required before layering custom dark-sidebar CSS — without it, Streamlit's dark theme overrides everything.
2. CSS `:has(.child-class)` on a flex parent + `margin-top: auto` is the cleanest way to sticky-bottom a Streamlit sidebar element without `position: fixed`.
3. Don't build UI edit forms unless Ming explicitly asks for them — profile display ≠ profile edit.
