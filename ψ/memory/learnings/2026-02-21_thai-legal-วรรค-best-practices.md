## 1. ความหมายของ "วรรค" ในกฎหมายไทย

วรรคคือ **หน่วยกฎหมาย** ไม่ใช่แค่ย่อหน้าทางภาษา แต่ละวรรคมีผลทางกฎหมายแยกกัน ("ตามวรรคหนึ่ง", "วรรคสอง") โครงสร้างทั่วไป:

- **วรรคหนึ่ง**: บทบัญญัติหลัก
- **วรรคสอง/สาม/...**: ข้อยกเว้น, กรณีพิเศษ, ขั้นตอนปฏิบัติ
- รายการ (๑)(๒)(๓) = อยู่ **ภายใน** วรรค ไม่ใช่วรรคใหม่

---

## 2. สัญญาณ "วรรคใหม่" (Split Here)

| Pattern | ตัวอย่าง | หมายเหตุ |
|---------|---------|---------|
| ขึ้นต้นด้วย "ในกรณีที่..." | "ในกรณีที่มีการแก้ไขสัญญา..." | วรรคแยก เกือบทุกกรณี |
| ขึ้นต้นด้วย "หลักเกณฑ์ วิธีการ..." | "หลักเกณฑ์ วิธีการ และระยะเวลา..." | wrap-up clause = วรรคสุดท้าย |
| ขึ้นต้นด้วย "องค์ประกอบ องค์ประชุม..." | "องค์ประกอบ องค์ประชุม และหน้าที่..." | sub-provision สำหรับคณะกรรมการ |
| ขึ้นต้นด้วย "เมื่อ..." (ไม่ใช่ continuation) | "เมื่อหัวหน้าหน่วยงานให้ความเห็นชอบ..." | วรรคใหม่ |
| ขึ้นต้นด้วย "ผลการดำเนินการตาม..." | "ผลการดำเนินการตาม (๔)(๕)..." | วรรคสรุปผล |
| ขึ้นต้นด้วย "หากประธานหรือกรรมการ..." | บทบังคับเพิ่มเติม | วรรคใหม่ |

## 3. สัญญาณ "ต่อเนื่อง" (Do NOT Split)

คำเหล่านี้ที่ขึ้นต้นบรรทัด = **ต่อจากวรรคเดิม** ไม่ใช่วรรคใหม่:

```
ทั้งนี้       ดังต่อไปนี้    โดย           เว้นแต่ (ต้นบรรทัด)
ซึ่ง          อันได้แก่      ตาม           และให้
แต่ทั้งนี้    ดังนี้          ประกอบด้วย    จากนั้น
นับแต่        ดังกล่าว       เป็นต้น
```

ตัวอย่างอันตราย: "ดังต่อไปนี้" ที่ท้ายบรรทัดก่อน = รายการที่ตามมาเป็นส่วนของวรรคเดียวกัน

## 4. OCR Artifacts ที่ต้องระวัง

### 4a. Trailing Topic Heading (พบบ่อยที่สุด)
หัวข้อของ **มาตรา/ข้อถัดไป** หลุดมาท้ายมาตราปัจจุบัน

```
...ให้เจ้าหน้าที่ดำเนินการต่อไปได้     ← จบมาตรานี้
คณะกรรมการซื้อหรือจ้าง               ← หัวข้อมาตราถัดไป (ต้องตัดทิ้ง)
```

**วิธีตรวจสอบ**: บรรทัดสุดท้ายสั้น + ไม่มี legal content markers + บรรทัดก่อนจบด้วยคำสิ้นสุดประโยค

**คำสิ้นสุดประโยค (sentence-final)**: ได้, แล้ว, ต่อไป, ไป, ไว้, นั้น, นี้, ด้วย, เท่านั้น, ทันที, โดยเร็ว, อนุโลม, กำหนด, เหมาะสม, ที่สุด, กรณี

### 4b. Word Wrap
OCR แบ่งบรรทัดกลางคำ/กลางประโยค — ไม่ใช่วรรคใหม่

### 4c. Blank Lines
บรรทัดว่างใน OCR = artifact ไม่ใช่ตัวแบ่งวรรค (ยกเว้นถ้ามีหลายบรรทัดว่างต่อกัน → อาจเป็น section break)

### 4d. Structural Headers
หมวด/ส่วน/ภาค ที่ปรากฏในช่วงท้ายของมาตรา → ตัดทิ้ง (เป็นหัวของหมวดถัดไป)

### 4e. Signature Block
"ผู้รับสนองพระราชโองการ", "ประกาศ ณ วันที่" → ตัดทิ้ง (เป็น footer ของเอกสาร)

## 5. กลยุทธ์ Fix ตามลำดับความสำคัญ

```
1. Rule-based trim (ตัด trailing headings, signature blocks)
        ↓
2. Rule-based merge pass (continuation words → ไม่ split ที่ขึ้นต้น ทั้งนี้/ดังต่อไปนี้/...)
        ↓
3. Gemini semantic split (ให้ AI ตัดสินในกรณีที่ไม่ชัดเจน)
        ↓
4. Manual JSON cache patch (สำหรับ Gemini ที่ split/merge ผิดซ้ำๆ)
        ↓
5. ยอมรับ OCR gap (ถ้าข้อความต้นฉบับหาย = แก้ไม่ได้)
```

---

## 6. ความล้มเหลวของ Gemini (และวิธีรับมือ)

| ปัญหา | สาเหตุ | วิธีแก้ |
|-------|--------|---------|
| Over-split | เห็น "ในกรณีที่..." เป็นวรรคใหม่เสมอ แม้จะเป็น continuation | Rule-based merge pass (Pass 2) |
| Under-split | เนื้อหาเดียวกัน → รวมเป็นวรรคเดียว | Manual split ใน JSON cache |
| Non-deterministic | Text เดิม → ผลต่างกันในแต่ละ run | ต้อง verify ด้วย reference (Excel) |
| ไม่รู้จัก OCR artifacts | เห็น trailing heading เป็น content | ต้องใช้ _trim_trailing_structure ก่อน |

---

## 7. การ Validate

**Primary**: เทียบกับ reference จากผู้เชี่ยวชาญ (Excel ที่นับวรรคด้วยมือ)

**Robustness test**: run `--resplit` (Gemini) 3 ครั้ง — ถ้า diff count คงที่ = framework แข็งแกร่ง

**OCR gap check**: ถ้า got < expected และข้อความในไฟล์ไม่มีเนื้อหาพอ → บันทึกว่า "OCR gap" อย่าพยายาม fix ด้วย parser

---

## 8. สรุปหลักการ

> **วรรคคือหน่วยกฎหมาย ไม่ใช่หน่วยภาษา**
> รายการ (๑)(๒)(๓) อยู่ในวรรค — คำ "ทั้งนี้/ดังต่อไปนี้" ต่อจากวรรคเดิม — "ในกรณีที่..." มักขึ้นวรรคใหม่
> OCR สร้าง noise มาก: trailing headings, word wrap, blank lines ไม่ใช่ paragraph breaks
> Fix ด้วย rules ก่อน ให้ Gemini ตัดสินทีหลัง patch JSON สุดท้าย
